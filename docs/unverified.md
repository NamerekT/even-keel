# What has not been verified

Even Keel is checked live on the author's machine with the author's accounts. Some behaviour could not be checked there: the situation never came up, or there was no way to create it. These pages list it, so you know where Even Keel works on an assumption. Each entry says what is assumed, what happens if the assumption is wrong and what to do about it.

If you run into one of these, please open an issue with what you saw: it is the only way the entry gets checked. What has been checked is in [verified.md](verified.md).

When code removes a behaviour, retire its entry and index row only after checking that its permanent ID is no longer referenced in code (`git grep -n -F -e '<ID>' -- src`, including `rare: <ID>` log keys). If a reference remains, keep the entry and report it. Otherwise append a row to `docs/verified/<area>.md`: `entry <ID> retired: the behaviour was removed by <task>`, with the removing commit and date and a `retired` result. This is a retirement record, not a live check; live-run fields are not applicable. An entry is never silently deleted and its ID is never reused.

The weekly [unverified-audit skill](../.claude/skills/unverified-audit/SKILL.md) reviews stale and bloated entries. `npm run unverified-audit` prints a read-only Markdown report; later code changes are candidates for review, not proof that an entry is obsolete. The audit preserves checked history in the verified log and leaves manual check tasks for the user to decide.

## Areas

The entries are kept in one file per area. [What has been verified](verified.md) has the same areas under the same file names, so one thing is looked up in the same place in both.

- [Platforms](unverified/platforms.md) — macOS, Node.js versions, the start at sign-in
- [Updating](unverified/updating.md) — the update button, npm, Huly's client, plugin marketplaces
- [The page](unverified/page.md) — the header, the setup wizard, a chain's pauses as the page shows them
- [Accounts](unverified/accounts.md) — sign-in, plans, extra and paid subscription usage
- [Claude limits](unverified/claude-limits.md) — Claude's usage windows, their resets and polls
- [Sessions](unverified/sessions.md) — Claude Code sessions and what every agent shares: the CLI copy, the Agent SDK, recovery, handoffs, the chat, API keys, Protection
- [Codex](unverified/codex.md), [OpenCode](unverified/opencode.md), [Copilot](unverified/copilot.md) — that agent's sessions, sign-in, limits and stats
- [Packages](unverified/packages.md) — plugins and MCP servers of a project's set, the gateway
- [Trackers](unverified/trackers.md) — tracker profiles, statuses, OAuth, task feeds
- [CI](unverified/ci.md) — CI runs, commands after a green main, conflicts
- [Machines](unverified/machines.md) — the link between a hub and its machines

A new entry goes into the file of its area, under a `##` heading that names the behaviour (and its task, in brackets), and gets a row in one of the tables of "What to check first" below that links to it (`unverified/<area>.md#<heading>`). An entry that fits no area goes into the closest one; a new area is a new file here and in `verified/`, and a line in both lists.

## What to check first

Every entry has exactly one row in the tables below. The number in the first column is the entry's permanent ID: it is never changed, never reused and never renumbered to a new order, because the code's rare-event keys, the log, the rows of [verified.md](verified.md) and the check tasks name an entry by it. A new entry takes the next free whole number (one above the largest ID in the tables, no letters, no number "between" two others). Inside a section the rows go by ID, ascending: the number first, then its letters, then the digits after them (0, 0a, 0b, 1, 1a, 37f2, 37h1), so a new row goes where its ID falls.

The section says how soon an entry should be checked:

- **Check first** — the entry hits everyone by default (its "Who it hits" cell has no condition: no setting turned on, no platform, provider or plan) **and** the chain stops or work is lost if the assumption is wrong.
- **Then** — everything else that can be checked. When in doubt between the first two sections, a row goes into this one.
- **Waiting for the event / not checked by choice** — entries that wait for a natural occurrence, and two that are not checked on purpose.

The **Task** column is the manual "Проверка" task that checks the row, or "—" while no task has taken it. This list is an index: a row is an entry, what it hits and the task that checks it, nothing else. What a run checked, what is left, what a check needs and why an entry waits go into the entry itself or the check task, never here; a run narrows the entry, not this list. A new entry gets its section by the criteria above and an empty Task until a task takes it.
