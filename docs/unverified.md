# What has not been verified

Even Keel is checked live on the author's machine with the author's accounts. Some behaviour could not be checked there: the situation never came up, or there was no way to create it. These pages list it, so you know where Even Keel works on an assumption. Each entry says what is assumed, what happens if the assumption is wrong and what to do about it.

If you run into one of these, please open an issue with what you saw: it is the only way the entry gets checked. What has been checked is in [verified.md](verified.md).

## Areas

The entries are kept in one file per area. [What has been verified](verified.md) has the same areas under the same file names, so one thing is looked up in the same place in both.

- [Platforms](unverified/platforms.md) — macOS, Node.js versions, the start at sign-in
- [Updating](unverified/updating.md) — the update button, npm, Huly's client, plugin marketplaces
- [The page](unverified/page.md) — the header, the setup wizard, a chain's pauses as the page shows them
- [Accounts](unverified/accounts.md) — sign-in, plans, extra and paid subscription usage
- [Claude limits](unverified/claude-limits.md) — Claude's usage windows, their resets and polls
- [Sessions](unverified/sessions.md) — Claude Code sessions and what every agent shares: the CLI copy, the Agent SDK, recovery, handoffs, the chat, API keys, Protection
- [Codex](unverified/codex.md), [OpenCode](unverified/opencode.md), [Copilot](unverified/copilot.md) — that agent's sessions, sign-in, limits and stats
- [Packages](unverified/packages.md) — plugins and MCP servers of a project's set, the gateway
- [Trackers](unverified/trackers.md) — tracker profiles, statuses, OAuth, task feeds
- [CI](unverified/ci.md) — CI runs, commands after a green main, conflicts

A new entry goes into the file of its area, under a `##` heading that names the behaviour (and its task, in brackets), and gets a row in "What to check first" below that links to it (`unverified/<area>.md#<heading>`). An entry that fits no area goes into the closest one; a new area is a new file here and in `verified/`, and a line in both lists.

## What to check first

Every entry, ordered by how many people it reaches and how badly it hurts them if the assumption is wrong: the lower the number, the sooner it should be checked and the more a run into it costs. Each row links to the entry.

Waiting-list entries 86, 18, 17c, 29 and 46 can be checked after a natural occurrence with `grep "rare:" logs/even-keel.log` (on PowerShell, `Select-String 'rare:' logs/even-keel.log`). Match the observation and its outcome; an absent line proves nothing. Observation keys and open pairs are kept in the state database (`rare_events`, `docs/storage.md`) for 30 days, so a service restart reports no event twice and still writes the second line of a pair; only a failed database write can repeat a line. These diagnostics do not change session control.
