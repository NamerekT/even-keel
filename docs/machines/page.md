# Machines on the page

What the pool, a machine and the machines panel show.

## The pool on the page

BTN-1271: the tab "Machines" of a project's settings (`web/src/pages/ProjectMachinesTab.tsx`), shown only where the hub has more than one machine; a tab open when the last machine elsewhere goes gives way to "Repository".

**"More than one machine"** (BTN-1552) is counted the same everywhere — the header's machines panel, this tab, "+ Machine" under "Hub address for machines", the shared settings' capacity and "Go on where a limit is left": by the live machines, `liveMachines` of the state (`MachineNetwork.live`: the own machine and the joined ones not revoked, as `machineCards` lists them), through `severalMachines` (`web/src/machineView.ts`). `machineNames` keeps every machine the hub ever had, to label old sessions and lanes: a hub restored on another computer keeps its old own machine there, revoked, and counting by it would hide "+ Machine" with one live machine. A machine coming online that `refresh` has not read as joined makes the hub read its machines anew, so a just-joined one counts at once. `/stats` keeps its machine select by `machineNames`: it filters history, the revoked machines' too.

- **The rows** come from the query `machines/pool` (`MachineNetwork.pool`, `ProjectPool`): every machine of the project's pool with its folder there (the own one's is the project's repository; a machine elsewhere's is `project_machines.folder`, step 58, else the project's folder name under the machine's folder of projects), online or not, and the project's slots as a tag. Its switch is the command `machines/enable` and applies at once, not through the settings' draft; a machine turned off is still briefed and finishes the task it holds. The page reads the pool again at each `machines` event and when a command or a job of the project ends.
- **The project's width** is a field of the same tab, drafted and saved with the other settings (`docs/settings.md`). So is the switch "Lanes by component" under it, shown only where the project's tracker names components (its vocabulary, `useVocabularies`) or the switch is already on.
- **"Connect"** (`web/src/pages/ConnectMachine.tsx`) lists the joined machines not in the pool (`others`). The own machine, out of the pool, is just turned on. A machine elsewhere takes one folder field with its state under it, the same as a machine's row in the wizard (`MachineFolderField`, BTN-1298; "The folder's state" below, asked with `{machine, folder, project}`): the machine's folder of projects and a name (the project's folder name by default), or "another folder…" with a full path (the only way when the machine did not report its folder of projects, `ProjectPool.others[].root`); a taken folder keeps "Connect" off. There is no switch between a clone and a folder already there: the folder decides. The command `machines/connect` (`clone` absent — `auto`; `true`/`false` still force either) starts a step job (the window of BTN-1048, `docs/web/wizard-repository.md`, "The creation job"; kind `machine`, `StepJob.project` set) of `connectPlan` (`src/service/machine-pool.ts`): `machine-clone` (with `auto` it probes the folder first: a clone of the project there is taken, a taken folder fails with its notice, a free one gets a clone from the hub's `origin`, else its first remote, its progress in the window; the clone stands on the project's `branch`, not the remote's default one, and a remote without that branch is refused `git.noRemoteBranch`, BTN-1566), `machine-place` (the folder into the pool turned off and the machine briefed, so its packages start installing; a folder outside the machine's folder of projects is refused, `pool.outside`), then the checks on the machine (`src/machine/folder-check.ts`, the machine's services group `folders`): `machine-repo` (a git repository), `machine-remote` (one of its remotes is one of the hub's, the scheme and `.git` apart), `machine-branch` (the project's `branch` is there, locally or as the project remote's copy, and the checkout stands on it: sessions merge into the branch the checkout stands on. A clean checkout elsewhere is switched onto it, `git switch` or `git switch --track <remote>/<branch>`, with a line in the machine's log; one with uncommitted changes to tracked files is refused `pool.dirtyBranch` and left as it is, a switch git refuses is `pool.switchFailed` with git's words; BTN-1566), `machine-trust` (only for Claude Code: the folder is trusted in an account folder of the machine), `machine-packages` (waits up to a minute for an installation under way, then refuses with the packages not ready), `machine-push` (`git push --dry-run` of the branch onto itself: nothing is sent, yet the forge checks the right to push; with no fetch, a remote branch gone ahead of the folder's copy is refused by git as `[rejected] (fetch first)` or `(non-fast-forward)` after the forge answered, and that passes, BTN-1513), and `machine-enable`. A failed check stops the job with a notice code that says what to do (`pool.*`), and Retry runs it again; the machine is not turned on. Cancel takes the machine out of the pool only if the job put it there; a clone made stays on the machine. A machine off the link fails a step with `pool.offline`.
- **The wizard** (BTN-1297, `web/src/pages/WizardMachines.tsx`, the picks' logic in `machinePicks.ts`): with a joined machine elsewhere, the step "Repository" of a git project holds the block "Machines" in place of the field "Folder" — a row per machine of `machines/cards` (its label, "this machine", the OS, "online", a tag per agent it has a signed-in account of) with a checkbox; a ticked row opens its folder: the machine's folder of projects and a name, or "another folder…" with a full path, and the folder's state under it. Unticking folds the row and keeps its values.
  - **The folder's state** is the query `machines/folder` {machine, folder, remote} (`probeOn`, the machine's `folders.probe`, wire API 14), or {machine, folder, project} for a project already made, against the remotes of its hub folder (`probeProject`, BTN-1298), read 500 ms after the last keystroke (`useFolderAnswers` in `web/src/pages/MachineFolderField.tsx`): `free` (a clone goes there), `clone` (a clone of the project's remote is there and is taken) or `taken` with the notice of what to do (`pool.folderNotEmpty`, `pool.foreignRepo`, `pool.outside`, `pool.noGit`); a taken folder keeps "Next" off (`machinesMissing`). The hub's own row says "free — Even Keel creates it", or for a new folder the path of the field above.
  - **No repository of the project on the hub** (BTN-1554): its `repo` gone or no work tree, as after a hub moved to another computer (`repositoryRemotes` in `src/projects/remotes.ts` answers `null`, unlike a repository with no remote, still `pool.hubNoRemote`). The spec's `remotes` is then `null`, and the machine takes the folder's own remote as the project's, `origin` first (`mainRemote`, `src/machine/folder-check.ts`): a repository with a remote is `clone` with the note `pool.hubNoRepositoryTaken`, one without is `pool.folderNoRemote`, and the checks `machine-remote`, `machine-branch` and `machine-push` go by that remote. A free folder, and a clone asked for, are refused `pool.hubNoRepository` (nothing to clone from; its button opens the project's Repository tab). No refusal names a blank remote: `pool.foreignRepo` and `pool.otherRemote` come only with one.
  - **Without a remote only the hub**: a new folder or one without a remote puts a warning over the list, and the other machines are off with "needs a remote"; their ticks come back with an address. A machine off the link is off with "connect it in the tab "Machines" once it is back".
  - **No agent signed in** (none of its agents, `MachineCard.agents` empty): the row's chip "no agent signed in" and, opened, a band with "Sign in on <machine>" — one hub account fit → `machines/login` at once, several → the account picked, none → "Add account" with that machine picked. The project still connects; tasks do not go there until an agent signs in.
  - **The hub can be unticked**: `ProjectDraft.here` false, and the own machine is turned off in the pool once a machine elsewhere is on (`only` of `connectSteps`).
  - **Creation**: `ProjectDraft.machines` (`DraftMachine` {machine, folder: the full path}) and `onMachines` add each machine's steps of `connectSteps`, `clone: 'auto'` (a free folder is cloned, a clone there is taken), after the project's own, their ids `<step>@<machine>` and `StepDef.group` the machine. A step of a group that fails skips the rest of its group, keeps its notice on the step (`JobStep.failure`; `JobWindow`'s refusal over the buttons then has a line per such step, named by its machine, with its fix — never inside the scrolling list, where it could stay below the fold) and the job goes on; once its steps are through the job fails with the first such notice and Retry runs the failed groups again. Cancel before the project is kept takes back all.
  - The summary "What will be made" has the fact "Machines and folders": each ticked machine's label and full path.
- **`dev:fake`**: `?machines=signIn` names four machines, so the tab shows; "Connect" on the laptop fails at `machine-push`, on the desktop it is done at once (`web/src/live/fakeMachines.ts`). In the wizard (`/projects/add?machines=signIn`) the laptop has no agent signed in and "Example mini" is off the link; a folder named with `clone` answers `clone`, with `taken` another repository.

## The machine's page

BTN-1272: `/machines/<id>` (`web/src/pages/MachinePage.tsx`), one page for the own machine and a machine elsewhere. It opens from a machine's name in a project's "Machines" tab and from a chain row's machine tag (`web/src/ui/MachineTag.tsx`, each name a link); a revoked or unknown id shows "No such machine".

- **The query** `machines/view` (`MachinePage`, built by `machinePageControl` in `src/service/machine-page.ts`, wired in `src/service/hosting.ts`): the name, online, joined, the report (`MachineAbout`), the colour, the capacity, the pool's projects with the folder there (`MachineNetwork.foldersOf`), whether each takes tasks and whether its packages hold them (the mirror's `facts().projects`), the agents whose CLI its panel does not find, the sessions not finished and the folders another machine's mark holds; no accounts (BTN-1742): they are in the snapshot's `machineSignIns`, read by the machine's accounts page. A machine elsewhere's comes from its mirror (`LinkedMachine.mirror`); before its first snapshot the packages and sessions are empty. The own machine is always online, and its report, which the local link never sends, is read with `machineAbout` at the first open and kept in memory (`root` null: the own machine's projects are where their settings put them, so the page hides the folder of projects). The page reads it again at each `machines` event, every 15 s (sessions change without one) and after its commands.
- **The capacity** (`machines/capacity`, a whole number from 1): a machine elsewhere's is `machines.capacity`, read at its next snapshot; the own machine's is `parallel`, saved through `ConfigStore.saveParallel` and applied live as the shared settings' field was. With more than one machine the shared settings show `parallel` as "This machine's capacity" with a link here instead of the field.
- **The colour** (`machines/color`, `#rrggbb` or null): `machines.color` (step 59). Null is the colour of `MACHINE_PALETTE` (`src/link/colors.ts`) by the machine's place among the hub's machines, oldest first: eight muted colours, each at least 64 apart in RGB from every `--series-*` account colour of both themes (`web/src/machineColor.test.ts`), so a machine's icon never reads as an account's dot. The state carries every machine's colour (`machineColors`, `MachineNetwork.colors`) and the own machine's id (`ownMachine`); the colour fills the machine's icon (below), never a label's background. The page offers the palette's swatches, a free pick (sent once it rests 0.4 s) and "The palette's colour" for a picked one (`paletteColor`, `MachineNetwork.paletteColors`). A colour shows at once (BTN-1515): at a click, at each step of the picker's drag, the palette's at its button — in the head's name and in `MachineStrip` under the header, which the page paints through `usePaintMachineStrip`; it holds until the page read after the answer lands (`reload` resolves then), and a refusal puts the saved one back; a colour as close to an account colour of the theme shown gets a quiet line under the picker (`nearAccountColor`).
- **The icon** (BTN-1595, `web/src/ui/MachineIcon.tsx`, the pure rules in `web/src/machineIcon.ts`) stands before a machine's name everywhere — the chain's tag, the labels, the panels, the pool, the pickers, the page's head — filled with its colour: a circle for the hub (`ownMachine`), a rounded square for a machine; inside, its system's sign (Windows a 2×2 grid, Linux `>_`, macOS a hollow ⌘, none for an unknown system) in a light or dark ink by WCAG contrast with the colour (`inkOn`); Docker shrinks the shape to 80 % inside a thin frame of the same colour. The state's `machineKinds` (`MachineKind`: `platform`, `container`) carry each machine's `about.os`/`about.container` (`kindOf` in `src/link/kinds.ts`, `MachineNetwork.kinds`), the hub's own from its process. The tip says it in words ("Hub, Linux, in Docker"). 20 px on rows and labels, 32 px in the page's head; `dev:fake` gives every combination (`FAKE_KINDS`), `?hubOs=linux` puts the hub on Linux.
- **The head** (BTN-1307) holds only the icon and the name, no fill, the chip "online"/"offline" and, for the own machine, the tag "this machine"; no line of statuses.
- **"On the machine"** gives each part of the report its own fact: the system, Even Keel (the version and a checkout's short commit), joined (a machine elsewhere), Node, git's version, git's name and e-mail — their values, a warning where unset (`MachineAbout.gitName`/`gitEmail`, optional: an older machine sends only `gitUser`, and the page shows one fact for both), the agents and the folder of projects. While the machine is online and git runs there, a button under the facts ("Set name and e-mail", "Change name and e-mail" once both are set, BTN-1503) opens the setup's window of name and e-mail (`IdentityButton` with `machine`): a field the machine has no value of holds the hub's own, a value the machine has stays its own, and Save is on without an edit while either is unset. It sends `machines/gitIdentity` {machine, name, email} (`machinePageControl.gitIdentity`): the own machine's is the hub's git (`gitSetup.identity`, the report read again); a machine elsewhere's is the link's command `git.identity` (`MachineNetwork.gitIdentity`, the group `git` of `MachineServices`), which writes `git config --global` there and answers what git reads back, put into `machines.about` at once and sent as `machines` without waiting for the next handshake; an offline machine is `machines.offline`. The project's machine settings ("<machine> in the project") have the same button in the row "Commit author" with the value (`MachineCard.gitName`/`gitEmail`). The agents are tags, one per CLI with its version (`machineAgents` in `web/src/machineAdd.ts`): a report names every agent it asked, `null` where no CLI is found as a launch looks for it, so only a version makes a tag; an agent the hub has accounts of and the machine lacks gets a warning tag such as "Codex: no CLI". The version is the CLI the agent's sessions run on (`cliReport` in `src/machine/cli-report.ts`, BTN-1502): Even Keel's copy while they run on one, else the installed CLI as `VersionWatcher` reads it — `EVEN_KEEL_<AGENT>_BIN`, `~/.local/bin`, a global npm install, not the PATH alone; `even-keel join`, which has no agents, asks each CLI found the same way (`installedClis`). The report goes at the handshake, but the page does not wait for the next one: the machine's accounts panel carries the live versions (`AccountView.clis`) and the page lays them over the report's (`withLiveClis` in `src/service/machine-page.ts`); the hub's own machine reads them anew on each view. `VersionWatcher.noticeInstalls` looks every minute whether a CLI appeared or went and then reads the versions again, so a CLI installed by hand shows within a minute without a restart or a new handshake.
- **Installing a CLI from the page** (BTN-1502). Where an agent's CLI is missing and the service could install it (`installableHere`: not in a container, which takes Even Keel's copy instead, BTN-1539), the accounts panel names the command per agent (`AccountView.installs`, `installCommand` in `src/agent/install-command.ts`: Claude Code's `install.sh`/`install.ps1`, a global npm install for the others) and the CLI card's "Install" runs it as the service's user (`account/installCli` {agent}, `CliInstaller` in `src/agent/cli-installer.ts`, one at a time, stopped after 10 minutes). Its output follows in `AccountView.install`; at its end the CLIs are looked for anew. On a machine elsewhere the same goes over the link (`machines/installCli` {machine, agent}, "Check again" — `machines/checkClis` {machine}): in the window "A new account on …" the tile of an agent with no CLI opens an install step (`MachineCliInstall.tsx`) with the command, its output, "Check again" and "Use the checked copy", which switches the hub's `cli.<agent>` to Checked with the download consent, so the machine downloads its own copy (BTN-1516).
- **The cards' buttons** are all small, `EmptyState`'s included; a project whose packages hold its tasks gets a warning chip "packages not ready" with the reason in its tip. The page has no card of accounts (BTN-1740): a machine's accounts, the hub's it lacks and its long-token folders are on its accounts page, `/accounts?machine=<id>` (`docs/machines/landings.md`).
- **"Other projects' memory"** (BTN-1648, `MachineMemoryCard.tsx`), a machine elsewhere only: its folders bound to the memory of a project, each with its project and path and "Unbind" on hover, and a project with a folder's path and "Bind" under them. `machines/memory` {machine, folders} sends the whole list (`machinePageControl.memoryFolders`: a known machine elsewhere, the hub's projects, a folder not empty, each pair once); it is saved, the machine briefed at once and `machines` sent. The own machine is refused (`machines.memoryOwn`): its folders are the hub's copies. `dev:fake`: the laptop starts with one binding.
- **"Disconnect"** sits behind the head's ⋯ for a machine elsewhere only and asks first: `machines/revoke`, as "A machine gone" says. The ⋯ of `MoreMenu` is as high as a small button everywhere it stands.
- **`dev:fake`**: `?machines=signIn` and `/machines/pc` (the own "Workstation", the state's sessions), `/machines/machine-1` (the laptop: a project whose packages are not ready, git without a name) or `machine-2`; `nocli` gives the laptop "Claude Code: no CLI"; a colour or capacity set there changes the state's `machineColors` and `chain.parallel`. `?chain=lanes` colours the chain's tags, and the backlog's ABC-20 there lands above the queue: its ghost (`#backlog`, hover its "Into the chain") stands right under both running lanes (BTN-1641); `?chain=elsewhere` runs ABC-6 on the home server with a session that has ended its first turn, shown from that machine's mirror. `?machines=follow` takes the laptop off the link with a checkout's commit and a failed catch-up with the hub; `?machines=container` makes it a container of 0.3.9 the hub refused, with the Compose steps (BTN-1440). `?machines=version` puts the laptop on another commit of the hub's protocol: the quiet tag at "Even Keel" and "Update", which moves it to the hub's build after 4 s; `?machines=protocol` puts it on another protocol: the card's "another build" and the page's band (BTN-1609). `?addMachine=new&updateBlocked=container` opens the window of a hub in a container: the address note, the Docker way first.

## The machines panel

BTN-1051: the view of one machine is a filter of the one chain, global and in the address (`?machine=<id>`, `MACHINE_PARAM`); none is "All machines", the page as before. With one machine there is neither the block nor the panel.

BTN-1575: a link within a page with the panel keeps the page's query — a chain or archive row (`rowLinkSearch`, `web/src/parents.ts`), the CI panel's fix task, a session's CI button, an account in the problems band — so the view does not change. A link that still drops `?machine=` is put back by `MachineFilterProvider` with `replace`, and until then the remembered choice stands as `selected`: no render shows "All machines", so neither the strip nor the header redraws.

- **The query** `machines/cards` (`MachineCard[]`, `machineCards` in `src/service/machine-cards.ts`, wired in `src/service/hosting.ts`): per machine its name, colour, own, online and since when it is off (`MachineNetwork.offlineSince`, kept in memory from the hub's start), whether git has a user, the agents it has an account of, by agent when its accounts free where all of them are at a limit, and its pool's rows. A machine elsewhere's comes from its mirror, the own one's from the accounts panel and git. `MachineFilterProvider` (`web/src/layout/MachineFilter.tsx`, around the app) reads it at each `machines` event and every 30 s, and keeps `?machine=` across the pages that have the panel: home, project, accounts, tools.
- **The header**: `MachineBlock` (`web/src/layout/MachinePanel.tsx`) is the first block of the right group — the machines' icon and their number; with a machine picked, a dot and a frame of its colour, the name in its tooltip. A machine off the link (BTN-1310, `machineCount`) turns the number into "online/all" (`2/3`) with an amber lamp after it, and the tooltip and `aria-label` name the machines off the link; a picked machine off the link has its dot hollow, the grey ring of its lamp in the panel, and says so in the tooltip. `MachineStrip` under the header: 3 px of the colour and a 34 px haze down, on a machine's page too (its colour, with one machine as well); `setColor` sends `machines`, so the cards and the strip of an open page with the panel take a new colour without a reload.
- **The panel** lies over the project's right column at its size (a fixed layer that copies the page's grid), elsewhere at the same width under the header; Esc or a press outside closes it. Cards: "All machines", then each machine with a stripe of its colour, a lamp and one line; a press filters at once, the icon in its head on hover opens the machine's page; "+ Machine" opens the add-machine window. "?" swaps the cards for the explanations of the lamps and the card.
- **The lamp** (`machineState`, `web/src/machineView.ts`), judged in this order for the project on its page, elsewhere for the projects of its pool: off the link (a grey ring, a pale card, "off the link for 2 h") → working (`--lamp-working`, the task it runs) → git without a user or packages not ready (`--lamp-error`, a red line) → every account of the project's agent at a limit (`--lamp-waiting`, "till 18:40") → free (a ring of `--lamp-done`, "next: ABC-7" — the first task of the order no lane holds, not skipped or waiting, not begun on another machine and of an agent it may run: a guess, not a promise).
- **The machine's view** (`machineChain`, `machineBacklog`): the chain without the tasks another machine runs or ran last (a session without a machine is the own one's), the fixes and carries on the own machine only, and the open tasks only where the machine is in the pool and may run them; no machine tags. The backlog keeps what it could take; CI is unchanged.
- **`dev:fake`**: `?machines=signIn` names three machines (the laptop's git has no user); `limit` puts the desktop's accounts at a limit till 18:40; `offline` takes the laptop off the link two hours ago; add `&machine=machine-2` for the desktop's view.
- **The cards' accounts** (BTN-1279): each card carries its machine's accounts panel (`MachineCardAccount`: folder, agent, e-mail, name, signed in, the limits it read, the sessions its panel counts and how its Claude sessions run — BTN-1570) and its launch account (`active`); a machine elsewhere's come from its mirror, empty before its first snapshot.
- **The header in a machine's view** (BTN-1279): the queue block and the waiting sessions are the machine's (`machineHeader`: its lanes, the queue's projects of its pool, the sessions of the tasks it runs or ran last); a drag in the queue keeps the other projects' places (`mergeQueue`). The accounts block: the own machine's view keeps the hub's `AccountBlock`; a machine elsewhere's is the same `AccountBlock` over the machine's accounts (BTN-1570, `MachineAccountsBlock` and `useMachineRows` in `web/src/layout/MachineAccounts.tsx`). `machineAccountView` (`web/src/machineAccountView.ts`) builds an `AccountView` of its own keys (`<agent>:<folder>`, `hub:<folder>` for a hub account not there), so no control of a hub folder reaches it: the machine's accounts with the limits it read and the hub's name and plan of the same agent and e-mail, its signed-out folders, then `hubGapsOn`. Pointing shows the hub's three levels as the machine takes them (`machineLevels`: each the machine's account of the hub's folder by e-mail, the shared one its own launch account); a level whose account is not signed in there says "not signed in on this machine" with "Sign in". A press opens the hub's narrow accounts drawer over the machine's accounts (`AccountPanel` with `machine`, BTN-1669) headed by the machine's label, only its accounts, its rows read-only (`MachineRows` in `web/src/layout/machineRows.ts`: no menu, problems or settings), "Used by" from `machineUses` over the projects of the machine's pool, a row not signed in there ("signed in on the hub, not here", "not signed in") last in its group with an info chip and "Sign in"; "Add account" opens the pick of the place on the machine, "All accounts →" the page `/accounts?machine=<id>`, where the full table of the machine's accounts is (`MachineAccountsPage`: limits, extra usage, sessions, "Runs through"). Colours are the hub's of the same e-mail (`rowSlot`). Info tone (`--accent`), not warn: the machine works without them. "All machines" shows one block with a lamp per account Even Keel uses (BTN-1309: the hub's launch account and pool, each machine's launch account, one per agent and e-mail, `headerAccounts` in `web/src/headerAccounts.ts`), its window a block per such account — the agent, the e-mail, its limits once (the hub's read first), and the labels of the machines it is signed in on (`MachineLabels`, a key on a long token, after four "+N" with the rest in its tip) — shown on pointing or keyboard focus; a press opens the hub's narrow accounts drawer (BTN-1669). A machine's label opens its page; a picked machine's window is headed by its label. The phone's menu opens the drawer of the view, a machine elsewhere's accounts in its view.
- **The settings tab** in a machine's view opens on the machine in the project (`ProjectMachineSettings`): its folder there (whole, under its name, wrapping only after a `/` or `\`), the pool's switch (`machines/enable`, at once), the commit author and whether the project's packages are ready there and, when not, why (BTN-1300): the machine's card carries from its facts the packages only the user makes ready there (`packagesUnready`, from `packagesPause`) and the tracker's MCP server no package brings (`trackerMissing`), a short line each with the names as tags and the whole sentence in its tip — the first fixed by "The project's packages", which opens them over the panel and its machine (`packagesOver` keeps the address's `machine` and hash, BTN-1301), so "Done" comes back to this tab — the second with the chain pause's buttons (`TrackerFix`) — and neither means what passes by itself (installing, starting, the gateway); the own machine's card has no facts, so it always reads ready there. The tab is a settings form (BTN-1729, `docs/design.md` "Settings form"): each name over its value, only the pool's switch at the column's right edge; the author's value is the name, then the e-mail on a line of its own, or the chip "not set", the packages' value the chip "ready" or "not ready" with the why under it, and each one's buttons under that (`.pool__block-actions`), at the start, in one row that wraps. "The machine's own commands" under it stands the same way, "Run no commands after a green main on this machine" a switch under the lists. The machine's page's card "The machine's settings" — the capacity with its button, the colour — too. A value never breaks inside a word (`WholeText`, `web/src/ui/WholeText.tsx`): an e-mail stands whole, a path wraps after its separators, and a piece too wide for the panel ends in an ellipsis with the whole value in a tip. `?machines=pooled` in `dev:fake` puts the laptop in the pool with a long author and folder. A machine outside the pool gets "Connect a machine", the tab "Machines"'s window for it alone; "The project's shared settings" shows the usual tabs, with a way back to the machine's.
- **The pages**: home shows the project cards and the launch chart of the machine's pool (`machineProjects`: a row of its pool, turned off too; on the own machine also the projects without a pool); `/accounts` of a machine elsewhere lists its accounts with their limits and the hub's that it lacks, with "Sign in" and "Add account" ("Signing in on a machine"); `/tools` offers the projects of its pool, and for a machine elsewhere says the table is of the hub's account folders (another machine's are not read over the link). `/status` lists the machines at the bottom, each with the panel's lamp and line and, for one blocked or off the link, a button to its page, whatever view is picked.
