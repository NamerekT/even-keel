# Schema steps: the rules and the newer steps

## The rules

- **Versions.** Versions 1 and 2 were the SQLite file (`PRAGMA user_version`); the numbering goes on in PGlite from 3. The version is the one row of `schema_version`. `STEPS[n]` takes the database from version `2 + n` to the next one in one transaction together with the new version, so step N gives version N, and a step that fails leaves the old version and none of its tables. `DATABASE_VERSION` is `2 + STEPS.length`.
- **A newer database** than the code is refused before anything is written: `storage.newerDatabase`, the blocked page (`src/start.ts`). So is a SQLite file of a version above 2.
- **Never edited.** A step is never edited or removed once merged. A schema change is a new step and a new frozen sample.
- **What an entry leaves out.** Unless its entry says otherwise, a step changes no file schema, its new tables start empty, a new column is null on the rows from before, and its frozen sample `test/fixtures/database-v<N>/even-keel.sql` holds the tables and rows of version N. The test an entry names checks the sample and the step over the sample of N − 1; an entry says what its sample holds only when that is the point. A step's columns mean what [the table](database.md#the-tables) says.
- **The tests of every sample.** `src/storage/database-schema.test.ts` compares every schema with its frozen sample (columns, indexes, constraints); `database.test.ts` and `database-settings.test.ts` migrate and read every PGlite sample whole (the settings and profiles also through a backup); `database-sqlite.test.ts` imports the SQLite samples `database-v1/` and `database-v2/`. They share readers in `database.fixture.ts`. A test of one step opens the database with `STEPS.slice(0, n)` rather than all steps, so a later step does not break it.
- **File schema versions** are another number: `SCHEMA_VERSION` (`src/storage/schema.ts`) versions the config's format (the imported file, `config-export`/`config-import`) and the files that stay ([`files.md`](files.md)). A change of a file format is a file schema version, a migration in `src/storage/migrations.ts` and a sample `test/fixtures/schema-v<N>/`; they are listed in [`steps-older.md`](steps-older.md#file-schema-versions).

## The machine database's steps

The machine's own database `state/machine/` has steps of its own (`MACHINE_STEPS`, `src/link/machine-store.ts`), under the same rules and numbered after the SQLite versions too: machine step k gives version k + 2. Its frozen samples are `test/fixtures/machine-v<N>/machine.sql`. What the tables hold is in `docs/machines/link.md` ("The stores") and `docs/machines/seam.md` ("The machine's stores").

1. The link's `outbox`, `commands` and `consents` (BTN-988).
2. `identity`, the connection token, the hub elsewhere and the folder of projects (BTN-1216).
3. `account_limits`, `account_settings` and `machine_state` (BTN-1246). The first start of the version moves the rows of the hub's two tables and `cli.downloaded` (`importMachineStores`) and marks it with `stores.imported`; a machine database made anew (lost, or out of step) takes them again as they were at the move. Test `src/machine/state.test.ts`.
4. `global_accounts`, `key_organizations`, `management_keys`, `left_folders` and `context_windows` (BTN-1250), version 6. They are moved under a marker of their own, `stores.hostImported`, so an installation past step 3's move still gets them; `cliCheck.history` and the pending `accounts.adoptLegacy` come with them, and the local CLI choices are kept as `cli`. `key_spends` and `task_retries` stay the hub's: the first receives deduplicated `key.spend` events, the second belongs to the hub's tasks server. Sample `machine-v6`; tests `src/machine/schema.test.ts` and `state.test.ts`.
5. `tally_files`, how far the machine's Tally collector has read each transcript (BTN-1280, `docs/tally/collector.md`, "Machines elsewhere"), version 7. Sample `machine-v7`.

The machine database is outside the hub's backups: a backup restored elsewhere brings those rows only as the hub's old tables held them at the move.
