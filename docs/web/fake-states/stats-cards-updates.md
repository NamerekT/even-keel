# Fake states: stats, cards, updates and the rest

The URL parameters of stats, task cards, the built-in tracker, saves, updates, CLI checks, git and chats.

| Parameter | What it shows |
| --- | --- |
| `?stats=off\|error\|empty\|newer\|restart` | stats are off for missing `.env` variables, the database is unavailable, there is no data, the database is at a newer schema version than the code (rolled back; `restart` — the build on disk knows it, the service was not restarted) — on `/stats` and in the project page strip |
| `?tally=off\|local\|server\|none` | the stats mode (BTN-247, `local` without it): turned off — `/stats` and the strip say so with a link to Settings → Stats; `none` — not chosen, `/` sends to the setup's stats step `/setup?step=stats`. Choosing a mode on the setup or in Settings → Stats changes it in the fake; a host containing `unreachable` is refused with `tally.unreachable` |
| `?rules=empty\|thin` | no rule changes, "Before and after" with a small sample |
| `?tools=bloated\|empty` | `/tools`: the last session with claude.ai skills, a failed MCP server, an account mismatch and a main checkout's `.claude/settings.json` the sessions do not get (in `.gitignore` on an odd letter, uncommitted edits on the rest); without transcripts. Projects on an odd letter (`ABC`, `OPS`) differ slightly in settings — for "Only differences". Every project has a local-only design plugin and `strata` permission of packages it does not have on, dropped by `forPackageOff` as the service drops them, so they are in neither the problems nor the matrix |
| `?card=empty\|links\|none` | a task card without description, labels, relations, comments, attachments, estimate and time (otherwise it has SVG pictures, an MDN CC0 video and a text file, the first comment a thread of two replies, and a task with an estimate its "Estimate" and, once started, a "Time" — every third task, as ABC-9, over ×1.5 in the warning tone); the full card with a parent and twelve related tasks, to scroll the card's side panel (BTN-1283); the tracker returns no card. "Into the chain" (in the card and in the backlog panel) moves the task from the backlog into the chain in the fake, to its `landing` place: ABC-18 into v0.2, ABC-19 into the folded v0.3, ABC-20 to the end; "To the backlog" (in the card and on a hovered chain row without a live session) moves a `ToDo` or `Active` task back into the backlog |
| `?card=builtin\|conflict` | every card is a built-in tracker's task, edited in place (BTN-771, `fakeBuiltin.ts`): ABC-5, ABC-7, ABC-9 are subtasks of the made-up ABC-16, ABC-10, ABC-11 and the backlog's ABC-18 of ABC-17, both under the root ABC-90, so a subtask shows the ancestor path and ABC-16 the Subtasks section; ABC-5 is current, so its "+ Add subtask" asks first, and ABC-16's milestone change asks about its subtasks. The task search answers from the fake tasks; links, parents, labels, milestones, deletion and new subtasks change the fake state. `conflict`: the first title edit is refused with `builtin.conflict`, the title changed meanwhile, and so is the first description save, its last paragraph replaced meanwhile |
| `?tracker=builtin\|card=builtin` + `components=empty` | the built-in tracker's components (BTN-1288, `fakeComponents.ts`): each project gets Server, UI, Tracker, Sessions, Stats and Billing, its open tasks round the first four, its closed ones in Stats, Billing with none (the tag "new"); a card's "Component" field, the estimate's pencil and the tracker window's "Components" tab change them while the page lives; a new name taken ignoring case is refused with `builtin.componentTaken`. `components=empty` — no component yet. Open the tab with `npm run shot -- '/p/ABC?tracker=builtin&chain=idle&lang=ru#settings' 'dialog[open]' --click '#settings-tab-tracker' --click '.source-line button:has-text("Настроить") >> nth=0' --click '#settings-tab-components'`, a card with `/p/ABC?tracker=builtin&card=builtin&task=ABC-7` |
| `?tracker=builtin` (milestones) | the built-in tracker's milestone table (BTN-1287, `fakeBuiltinMilestones.ts`): a project's milestones are those its tasks carry — the first active with a target of 30 November, the second planned for 20 December, the rest planned without one — plus ABC's empty `v0.4 — выпуск` (the tag "new") and two closed ones without tasks of the fake: `v0.1`, completed with 14 closed tasks (its "Delete milestone" off), and a canceled one with a long name. A save, a rename (the tasks follow it) and a deletion change them while the page lives; a taken name is refused with `builtin.milestoneTaken`. Open the tab with the components' command above ending in `--click '#settings-tab-milestones'`; `--click '.milestone-table__fold'` unfolds the closed ones, `--click '.milestone-table__row >> nth=0'` opens the editor, and `--click 'dialog .milestone-status button >> nth=2'` there the warning about open tasks |
| `?card=builtin&description=html\|long\|empty` | the built-in task's description (BTN-772): with raw HTML, so the editor opens in Markdown with Preview off; twelve parts, to scroll inside the editor; none, for the placeholder. Without `description` the shared card text without its Huly HTML table, so Preview takes it. A saved description stays while the page lives. Open a card with `/p/ABC?card=builtin&task=ABC-7` and press "Edit" |
| `?card=builtin&journal=empty\|long\|asked\|history\|history-long` | the built-in task's journal (BTN-774, `fakeJournal.ts`): none, 25 entries (the 20 newest shown, "5 more" under them), a session's question with the answer given in the chat and agent entries with their model; `history` — the default comments among changes of every kind (BTN-1112: creation, status, labels, estimate, milestone, Even Keel's moves, an agent's description difference, run and link); `history-long` — the same after 25 agent title changes under a long model name; without `journal` an agent report with its model, Even Keel's `NO CHANGES:` and the person's note. A note sent or deleted stays while the page lives. Open a card with `&task=ABC-7` |
| `?card=builtin&files=missing` | the built-in task's attachments (BTN-773, `fakeAttachments` in `fakeBuiltin.ts`): the shared card files with their captions and the trash button, plus `old-screen.png` whose file is gone ("No file" tile with its tip). A file pasted or dropped into the description editor is taken as an object URL and stays, like a deletion, while the page lives; an object URL is no `/api/tasks/…` address, so the saved description shows its name, not the picture. Open a card with `&task=ABC-7` |
| `?tracker=builtin` | the fake's Huly profile is the built-in tracker (BTN-770), so the project page has the add ghosts and the backlog tab at 0: every project's vocabulary names the milestones its tasks carry, ABC's also the empty `v0.4 — выпуск` (unfold v0.2 and v0.3 to reach it); XYZ is the empty project, DEMO the empty backlog. A task made by a ghost joins the fake chain after the last task of its milestone (or at its end), a backlog one on top of the backlog. Combine with `chain=idle` for the ghost without the running chain's tip. Those projects' settings name `builtin` as their tracker too (BTN-769), so Settings → Tracker → Configure has only "Project tasks" (XYZ: no milestone, "Only milestones" unavailable), and Status and Trackers and CI show the built-in card with its projects |
| `?tracker=builtin&export=clean\|prefix\|running\|comments\|waiting\|failed\|done\|held\|mismatch\|reports\|long` | Settings → Tracker → "Move to another tracker" (BTN-1075, `fakeExport.ts`). Without `export` the plan of a filled target loses labels, milestones, priority and a link, and "Move" passes a task through a step each 300 ms, every task through one step before the next (BTN-1194); `clean` — the plan loses nothing; `prefix` — the plan refuses the key as the project's own; `running` — a copy runs from the start; `comments` — it runs at the comments step, two tasks through it; `waiting` — it runs at the comments step, a step later stops moving and waits out the tracker's rate limit until 12 minutes after its start, the note naming that time (BTN-1190); `failed` — it stopped at the attachments step, three tasks through it, the band naming the task, the stage, the file and the reason (BTN-1455; wait for `dialog .notice--error`); `done` — every task is through and the switch waits (a switch turns the project to the profile's tracker); `held` — through, the switch refused while the chain works on the project, its current task and two released ones, each id a link to its card (BTN-1459); `mismatch` — through with a check short of two attachments until "Repeat" (BTN-1291); `reports` — the Tracker tab lists two transfer reports, the second switched past a check that did not match; `long` — the history loss counts every task, so with `chain=long` its tip lists 20 keys and "and N more" (BTN-1189). The switch "Move the closed tasks too" (BTN-1289) adds the project's closed tasks to the plan, Done and Canceled as their own status rows, and drops the plan's link loss. With `card=builtin&export=done` a card's parent and related tasks say "Moved to ABCGH-…". Open with `npm run shot -- '/p/ABC?tracker=builtin&chain=idle&export=done' --click 'button[aria-label="Settings"], button:has-text("Settings") >> nth=-1' --click '#settings-tab-tracker' --click 'button:has-text("another tracker")'` |
| `?import=refused\|reading\|running\|checking\|failed\|done\|held\|mismatch\|switching\|gone\|lost` | Settings → Tracker → "Move to the built-in tracker" of ABC on Huly (BTN-1406, `fakeImport.ts`). Without `import` the plan is read once, 120 ms a task with the meter "Read N of M" meanwhile, and a later ask answers at once (BTN-1452); the window closed mid-read drops it (`builtin/import/planStop`, BTN-1453), so the next one reads from 0; `reading` holds the read at 40 % (wait for `.transfer__meter`) with the note under it to keep the window open. The plan leaves behind two tasks' links to another project, the time reports and the milestones' closing time (BTN-1436), has four authors (an agent without a name, the user, two people, one with a long name; BTN-1416) whose picks the plan answers with and the first start keeps, and "Move" passes a task through a step each 300 ms, four steps, then checks a task a step with the meter "Check N of M" in place of the run's (BTN-1461); `checking` — the run is through and its check stands at 40 % (wait for `.transfer__meter`); `refused` — the plan refuses a project that had built-in tasks (`import.hadBuiltin`); `running` — an import runs from the start; `failed` — it stopped at the attachments step, the band naming the task (a link to its Huly card), the stage, the file and a reason with no message of its own (`StorageError (HTTP 503)`; BTN-1455; wait for `dialog .notice--error`); `done` — through, the switch waits (a switch turns ABC to the built-in tracker and lists its report under "Transfers"); `held` — through, the switch refused while the chain works on the project; `mismatch` — through with a check short of two attachments until "Repeat"; `switching` — through, and its switch goes on (BTN-1432): the last pass over three tasks, the check of every task, then the move, a step each 300 ms, the window showing the stage with its count; `gone` — through with a matched check and the line under it of an attachment Huly has no file of, the file in its tip (BTN-1454; wait for `dialog .transfer__none`); `lost` — an import runs and the state's reads after the first fail for 8 s, as a proxy's 502: the window keeps its meter with the warning "No answer from the service" and drops it with the next answer (BTN-1456; wait for `dialog .notice--warn`). The other trackers' projects have the button quiet (only Huly's, GitHub's and Linear's choices have `imports` in `fakeConfig.ts`). Open with `npm run shot -- '/p/ABC?chain=idle&import=done' --click 'button[aria-label="Settings"], button:has-text("Settings") >> nth=-1' --click '#settings-tab-tracker' --click 'button:has-text("built-in tracker")'` |
| `?card=readonly` | a tracker that cannot write labels. The card's run pick (BTN-508, BTN-983) needs no parameter: `state.runs` of the fake gives ABC-10 a run of Claude, `sonnet` and `high`, ABC-11 and ABC-15 OpenCode ones (ABC-15 with a long model), ABC-14 an effort alone; ABC-6 has a live session; Save answers `task/run` by rewriting the fake's run (`fakeSetRun`) |
| `?vocabulary=none\|fail\|slow` | the trackers name nothing / do not answer: the chain rules suggest only what the tasks carry (otherwise every project's tracker names `FAKE_VOCABULARY`, some of it on no task); `slow` — they answer 4 s late, so a label or milestone field pressed before that opens its list as the reading loader (BTN-1257) |
| `?save=slow\|lost` | a settings save (`settings`, `project/settings`, `profiles/rules`, `profiles/moves`) is answered at once, its state comes 3 s later (`slow`) or never (`lost`): the save bar holds "Saving…" with its buttons off, and under `lost` says after 15 s that the page has not got the values (BTN-1318) |
| `?fillMilestone=on\|off\|blocked\|long` | ABC-20 has no milestone: its preview joins the active milestone, keeps none with filling off, keeps none because of a later blocker, or has a long title. Moving it to Todo applies the preview's milestone too |
| `?backup=failed\|checkFailed\|none\|running` | the automatic copy of the state database (`web/src/live/fakeBackup.ts`, BTN-1083): the copy failed or did not open back whole (the red banner with "Open settings" to Backups, the last copy's fact framed red), no checked copy yet, a copy under way ("Copying…", the button off). | `?update=0.2.0` | a newer release: the toast in the corner, the mark next to the version in the gear menu and its notes in the update window (`web/src/live/fakeUpdates.ts`); "Update" turns into the progress toast |

| `?updateResult=done\|<step>\|rollback\|rebuild\|rebuildOnward\|rebuildMoved` | how the last update ended, as after the restart: `done`, failed at `<step>` (`build` by default) and rolled back, `rollback` when bringing the old version back failed too, `rebuild` for a hub restored to its previous commit, `rebuildOnward` for a failed rebuild whose rollback built the commit a chain merged meanwhile, `rebuildMoved` for one whose moved checkout stopped the rollback |
| `?updateProgress=settling\|running` | an update under way: waiting for the chains, or the update process running |
