# Fake states: the chain, backlog and session

The URL parameters that put the chain, the backlog, the chat and the session into a state.

| Parameter | What it shows |
| --- | --- |
| `/p/ABC?archive=many\|few` | The archive's older pages (BTN-1445, `fakeArchive.ts`): ABC's trackers hold 300 (`many`) or 20 (`few`) closed tasks beyond the state's, numbered down from twice that, every 7th canceled; each `archive/page` takes 700 ms, so the spinner of the pressed toggle or "K more" shows (`--click '.chain__toggle >> nth=0' --settle 150`). `#ABC-400` with `many` pages on to that task. |
| `/p/<key>?view=outside&outside=many\|none\|error` | The "Outside the chain" view (BTN-1428, `fakeOutside.ts`): each `outside/tasks` and `outside/archive` takes 600 ms, so the loader shows; by default seven tasks with an excluding label over v0.3, v0.4 and no milestone in In Review, In Progress, Todo and Backlog with mixed priorities (BTN-1673, for the status sections and the order switch), 31 in the old milestones v0.0 and v0.1 (folded unless the device keeps it open) and two in "Blocked", a status the rules count as closed; the folded "Archive" holds 14 closed tasks in pages of ten, so unfolded (`--click '.outside__archive .chain__toggle'`) it shows "older"; `many` gives the old milestones 140, for "Show more"; `none` the empty view and no archive; `error` the failed read with "Read again". |
| `?copies=missing\|downloading\|failed\|system-missing\|ready` | CLI copy consent, byte progress, retry and installation actions; `copyAgent=claude\|codex\|opencode\|copilot` picks the provider, `copySystem=missing` hides the Installed choice, `copyFailed=<provider>` fails a second provider's download beside it, `copyInstall=none` makes the machine one where no CLI can be installed (Docker, BTN-1539): no install command, the Latest choice and **Download the latest**. With `system-missing` on a machine that can install, the account panel names the command (`account.installs`), so the CLI's actions lead with **Install**; its press shows a running installer's output (BTN-1502). An explicit download completes after 3 s and opens account setup when started from the provider card. `copies=fresh` is a first run after BTN-603: every `cli` on `system`, Claude Code and OpenCode installed, Codex and Copilot not, no copy; `provider=` picks the chosen agent (`/setup?step=agent&copies=fresh&provider=opencode`). |
| `?protection=unsafe|unprotected|unknown|unavailable|protected|twoRemotes|opencode|opencodeUnsafe|opencodeCustom` | empty Protection rules with Codex bypass, remote branch audit verdicts (`unknown` includes a long remote name, `unavailable` a private GitHub repository on the free plan, EKR-121, `twoRemotes` the same unprotected branch on `origin` and `github` in one band, BTN-759), or OpenCode with default rules, no rules, or one custom command pattern |
| `?link=stale\|connecting` | connection states |
| `?long=on` | every project has a long name and every task a long title (`fakeLong.ts`), so the home cards' heads and the card's links wrap: the swatch, plaques, lamps and status dots stand by the first line; ABC-5 runs on OpenCode with a free OpenRouter model whose catalogue name is long, cut in the session's Model fact with the `free` badge after it (BTN-1348); `?long=mixed` gives a row of names in one, two and three lines (DEMO's two beside its `test` plaque), for the cards' level slots (BTN-1022) |
| `?families=3` | ABC's v0.1 rows belong to three parents that interleave (`fakeFamilies.ts`): ABC-16 holds 5 and 9, a new ABC-22 holds 6 and 8, ABC-17 holds 7 and goes on into v0.2 — three rails side by side; open v0.2 to see the third reach its rows (BTN-1162) |
| `?showTests=home,stats` | the "Test projects" switches as stored, for a page reloaded with them on (BTN-1364): `home` lays out DEMO's card, `stats` includes it on `/stats` with no `tests=1`; without it both are off, DEMO hidden |
| `?feeds=two\|five` | the empty XYZ files its tasks in two or five trackers (its Huly and GitHub, Linear, GitLab, Forgejo feeds): its card and `/p/XYZ` show one "Open in…" button and its list (BTN-1022); without it XYZ has its Huly page alone |
| `?chain=idle` | no active chain, to check starting one; "Start" and "New session" go through the start phases 3 s each |
| `?parallel=2` | two chains at once: DEMO, taken from the queue, runs next to ABC |
| `?chain=paused` | the chain is paused: "Resume" is the filled button and "Stop" stays pressable |
| `?chain=noBranch` | the chain is paused on `git.noBranch`: "Open the project's settings" under the error, to the Repository tab |
| `?chain=folderTaken` | the chain is paused on `machines.folderTaken` (machine "Example desktop"): "Take the folder over" under the error opens its confirmation, then takes the folder and resumes; `folderTakenGone` refuses the takeover with `machines.notTaken` in the dialog |
| `?chain=accountAbsent` | the chain is paused on `machines.accountAbsent` (BTN-1311, machine "Example laptop"): "Add account" under the error opens the add-account window with that machine picked; with `machines=signIn` the window goes on to the laptop's agents |
| `?chain=untrusted` | the chain is paused on `claude.untrusted`: one command pinned to the failed CLI/account and "Check again and resume" (as a Windows service, `runas` of the script `D:\even-keel\state\trust\ABC-5.ps1`; with `?host=terminal`, the PowerShell line); `untrustedLong` gives a long checkout path, `untrustedGlobal` clears the account override, `untrustedLegacy` keeps the old PATH commands; `trustWriteFailed` shows the file-repair notice, naming the account's `.claude.json`, without commands |

| `?chain=limit` | the chain is waiting for the limit reset |
| `?chain=limitsUnread` | after a restart the next launch waits for the first limits poll of its account (BTN-619): the band names the account and the next poll |
| `?limit=resume\|relay\|unknown\|credit\|codexCredit\|opencodeCredit\|copilotMonthly\|codex\|codexLong` | ABC-5 is held on a limit: a warm resume or a handoff after a known reset, an unknown reset, an API key out of credit, a Copilot monthly allowance, or a Codex task while the header's active account is Claude (also with a long account name). | `?chain=fixGroup` | a fix of main in the group (BTN-1617, `fakeFixGroup.ts`), one step every 3 s (`&gap=<ms>`): the group of ABC-5 (Workstation) and ABC-8 (Home server); main goes red mid-turn (ABC-5 parts and stands under the frame with "waits for main", the fix joins the group first); the fix lands (it goes to the archive, ABC-5 joins again). `&fixEnd=red` — main is red after the fix: the head lane pauses with ABC-5 current and its session stopped, outside the group, then resumes it. `&group=<n>` starts with the first n steps done (`group=1` — the fix in the group) |
| `?chain=reorder` | an order changed elsewhere (BTN-1612, `fakeReorder.ts`): every 2 s (`&gap=<ms>`) ABC-9 moves up past ABC-7 and ABC-8, then back under them; the rows glide in 0.15 s |
| `?chain=packages\|packagesSilent\|gateway` | ABC's next task waits for its packages: still starting (no button), forgejo does not answer ("Open the project's packages"), the MCP gateway does not run (the red banner, and each project's line points at it) |
| `?chain=machinePackages\|machineGateway\|machineOld` | ABC's lane went to Example laptop and its next task waits for the packages there, the hub's own being fine (BTN-1524, `fakeMachineLaneWait`): docs does not answer and forgejo is starting, the laptop's MCP gateway does not run, an older laptop only says its packages are not ready |
