# Page: the event log (BTN-350)

What happened while nobody looked: the service writes an entry for each event, a toast shows the warnings and errors that come while a page is open, and `/log` keeps them all.

## The service side (`src/event-log/`)

- `EventLog` (`log.ts`) holds the newest `EVENT_LOG_LIMIT` (3000) entries, loaded from the state database's `event_log` at the start (`loadEventLog`) and written behind (`docs/storage.md`, step 29). It is a queue: an entry over the limit pushes out the oldest, from the database too; nothing goes by age (BTN-780: a month was the other choice, the queue was taken since it needs no setting of time). An entry (`EventEntry`, `model.ts`) is an ascending `id`, `at`, a `level`, a `notice` (a code, translated on the page like any server message) and a `place` — where "Open" leads (`project`, `task`, `ask`, `backlog`, `ci`, `settings`, `packages` — the project's column on `/tools`, `accounts`) or `null`.
- Levels: **info** — launches, stops and settings; **warning** — what waits for a person (a question, a usage limit, work left in a folder, an uncounted CI failure, a CLI version Even Keel was not checked against, a project's package problem that does not hold its chain, an account's limits that cannot be read); **error** — what holds a chain (a red main, a carry conflict, a chain paused on an error, the MCP gateway failing, a config error, a package problem while the project's packages hold its chain, an account's limits not read until a restart).
- Sources:
  - The state the service builds for the page: `EventHub.watch('state', …, 2_000)` (`src/events.ts`) hands it to `EventLog.observe` at most every 2 s, also while no page listens. `watchedOf` (`watch.ts`) reads from it the page's events (`pageEvents`, `src/event-log/page-events.ts` — the toasts' events of before BTN-350: limit, red and CI red main, a question, a conflict, uncommitted or unmerged work), the CLI version warnings, the package problems, the accounts' unread limits, the gateway's and the config's errors, and each chain's pause and error. A chain paused on the limit or a red main writes no entry of its own: the event says it.
  - A CLI on a version Even Keel was not checked against is only in the log since BTN-780, the header has no banner of it: the installed CLI's entry opens Settings (its "CLI version", where Checked is chosen), a daemon's has no place — there is nothing to press for it.
  - A project's package problems (`ProjectPackages`: the set's own `problems` and those of each enabled package's cell, as /tools counts them) are an entry each, `eventLog.packages`, an error while `blocked`, else a warning; `installing` and `probing` pass by themselves and `unsupported` is the agent's, so they write none. The gateway's own error stays its entry. An account of a shared or project pool whose `/usage` is `unread` (a warning) or `off` (an error), as the header's usage banner tones it (`usageNotices`), is `eventLog.usageUnread`/`eventLog.usageOff`, its reason as the cause; a new `since` is a new entry. Both banners stay; the log keeps what they showed.
  - `observe` writes an entry for a condition that appears and for a chain that starts, stops, pauses, goes on or is held on a new error. A condition that goes and comes back is a new entry, a new toast: a carry conflict back after five minutes is news (BTN-780). Only a blink is the same one: back within `BLINK_MS` (5 s) of the first look without it — the state is built from parts read each on its own, and a failed or partial read may drop a condition from a build or two (one each 2 s window); the length guards against that, it was not measured. Nothing remembered yet (a fresh database) writes nothing: everything is old news.
  - The memory (`EventMemory`: the keys seen, when each was first missed, the chains' marks) is kept in `service_state` as `eventLog.memory`. At a start each remembered condition counts as seen at that moment and, for `GRACE_MS` (10 min) after the start, as held though not seen (`Restored`): the state is read in parts then, so a restart repeats nothing that held before it. The grace is only for those; a condition first seen after the start has the blink alone.
  - The service tells it directly: a launch from the launch log (`launched`, `src/service/chain.ts`), a session the chain stopped mid-turn (`stopped`), and every settings change (`settingsSeen` from the config store's `onChange` in `src/service/hosting.ts`: Even Keel's settings, a project's settings, a project added or removed; the first call only remembers). A fix of main or a carry has no task, so its launch and stop name the project (`eventLog.fixLaunch`, `carryLaunch`, `fixStopped`, `carryStopped`), not `ABC-FIX` as if it were a task (BTN-781). Settings changes are told by comparing `ConfigStore.raw()` as JSON, which depends on the order of keys: the store keeps its rows in one order (`sortedRows`, `src/settings/store.ts`) whether read from the database or just written, otherwise the first write from the page after a start logs every project as changed (BTN-781).
- The page gets the entries as `EvenKeelState.eventLog`; the hub sends them keyed by `id`, so a frame carries only the new ones.

## The page side

- **Toasts** (`web/src/layout/EventToasts.tsx`): one for each warning or error that came after the page's first state (`freshAlerts`); info goes only to the log. A toast holds `TOAST_MS` (12 s) of the page in sight: `visibilitychange` to hidden stops the count and coming back starts it over, so a toast is not missed in a background tab. At most `TOAST_LIMIT` (3) at once, an older one gives way. "Open" goes to the entry's place (`placePath` in `web/src/layout/eventLog.ts`), "Close" drops it; the entry stays in the log.
- **Unread** (`useUnread`): per browser, the id of the last entry read is kept in `localStorage` (`even-keel.eventLog.read`), live across tabs. A browser that never saw the log starts with all of it read (`useFirstReadMark`, called from `EventToasts` on every page, since on a narrow screen "Log" mounts only with the opened menu). The header's "Log" (`LogLink`) carries the count of unread warnings and errors, amber, red when one is an error; the narrow menu's row the same.
- **`/log`** (`web/src/pages/EventLogPage.tsx`): a card per day, newest first; a row is the time (full date in a tip), the level's dot with its name in a tip, the text with its projects as links, a "new" chip on what was unread at opening, and "Open" where the entry has a place — an arrow `.row-action` that shows on the row's hover or focus (`docs/design.md`, "Buttons"). Opening the page marks everything read. An empty log says what will show and has a button to the projects.
- Fake data: `dev:fake` has a day of entries of every kind (`fakeEventLog`); `?event=…` appends the entries of its event (`web/src/live/fakeEvents.ts`), `?log=empty` empties the log (`docs/web/fake-states.md`).
