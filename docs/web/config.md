# Page: live config and shared settings

## Live config (`src/config-store.ts`)

The settings are in the database since BTN-199 (`docs/storage.md`), and the service looks at them every 2 s, so a `config-import` applies on the fly too; every key with its levels and who writes it is in `docs/settings.md`. Every key applies at once (BTN-130): `ConfigStore.current` is the last valid parse, and `onChange(before)` lets the service rebuild what a key feeds (`projectsChanged` in `src/service.ts`: trackers, CI watches, packages, the chain of a renamed or removed project — `docs/chain.md`). The page has no restart marks. What still needs a restart is a few start-only environment variables (`docs/service.md`, "What applies on the fly"). `host` and `port` are not config keys any more (BTN-117): the address is `EVEN_KEEL_HOST`/`EVEN_KEEL_PORT` (`listenOf`), and an imported file that still has them gets one warning in the log. Settings that do not parse (written past the checks) — the last valid ones keep working, the error goes to the log, to a banner on the page (`ConfigBanner`) and, when its notice names a field (`fieldOf`, `web/src/pages/settingsField.ts`), under that field.

The page edits the settings; a hand edit is `config-export`, edit, `config-import`. `EvenKeelState.config` (`ConfigView`, built by `formsOf`) holds the effective values as forms — `shared: SharedForm`, `projects: Record<key, ProjectForm>` — with the trackers the form can pick (`TrackerChoice`, with the key a project names its tracker project by). Saving takes the settings in the config's format (`ConfigStore.raw()`), sets the keys of the fields the form changed (`withProjectForm`, `withSharedForm`), parses the whole result with `parseConfig` and, only if it parses, applies it and writes it into the database behind. "Changed" is against the base the save sends with the form (BTN-128): the values its draft started from, not the settings as they are now, so a field imported under an open form is not written back over (`baseOf` in `src/server.ts`, a missing base is `request.required`). A value the form did not change keeps its key as written, even if it repeats what it would inherit; a changed one is written only where it differs from what it would inherit — a project's `brief` and `chain` rules from the shared ones, a shared key from the default — otherwise its key goes; a project's `tracker` is always written, it inherits nothing (BTN-345). A project clearing `active` or `terminal` over a shared list writes `null`: back to the status categories. A string project entry becomes `{ repo }`, an empty value removes its key, an empty `commands` goes away; comments are impossible in JSON anyway. `commands` is an object so that commands after the agent's work get a key of their own; an unknown key in it is a config error.

The draft (BTN-128, `web/src/pages/settingsDraft.ts`, pure, with tests; `settingsStore.ts` holds it): a `{ base, edit }` per field, kept at module level per scope (`project:<KEY>`, `shared`) — closing the panel, Esc or leaving for Backlog/CI keep it, a reload drops it. A field typed back to its base is not changed. A changed field gets a stripe and an undo arrow in its head line, after the name and the chips, with "was: …" in the arrow's tip (`marksOf`): nothing is added under the field, so a change moves nothing on the page (a grid cell's arrow goes in its column's head, `cellMark`; a field without a head puts it beside its buttons or in its section's heading). A field kept own by an `own*` flag has one arrow for the flag and its values (`Marks.note` with several keys): "was: shared" when it turned own, else its value; the checkpoint shares keep an arrow per share while they stay own, and one in the group's head once they turn own or shared. In the chain rules' tables the row reset shows only on a row whose value differs from the inherited one, not on every row of an own list; a changed tab gets a dot (`UnsavedDot`), and so does the outer Settings tab when any group is changed (`useSettingsDirty`). The sticky bar at the bottom (`SaveBar`) shows only when the open group is changed, and holds its place while hidden, so its showing up neither moves the form nor covers the last field; in the side panel it sticks to the card's edge (`bottom` takes the panel's padding back, else the fields show through below it): gray undo reverts the group, the green check saves only its fields, a save error goes under its field. When the settings change under a draft (`rebase`), untouched fields take the new values silently; a field changed in both gets "the file now has: …" in the arrow's tip, and its undo goes to the stored value, while saving overwrites it on purpose. Each such change is kept into the stored draft (`settled`, BTN-598): a field saved and then changed back by the service — the CLI dialog's "Use installed CLI" after a save of "Checked" — starts from the saved value, so it takes the service's value instead of showing the old edit again.

### Token fields and browser suggestions

A token count — `context.window`, `stats.checkpointTokens`, `autoCompactWindow`, `codexAutoCompactWindow`, `openCodeAutoCompactWindow`, shared and per project — is a `TokensInput` (`web/src/ui/TokensInput.tsx`, the parsing in `tokens.ts`, with tests): it takes `300000`, `300,000`, `30.000`, `300 000`, `300k`/`300к`, `1.5k` and `1m`, groups the thousands with a comma while they are typed, keeps the caret among the same digits, takes a Backspace or Delete on a separator for the digit beside it, and turns `300k` into digits on blur. The draft holds the digits without separators, so a count typed back as it was is no change. Every text field of the page has `autoComplete="off"`: the browser's history of earlier values is noise in settings, names and searches; only the git name and email of the setup keep `name`/`email`, and secret fields get theirs from `secretInput`.

### Table drafts

`Draft.adding` keeps a table's unfinished row with its field (`PendingRow`: cells, encoded field value, validity and whether validation was shown). Text other than whitespace starts a row; an automatically chosen select does not. The field and tab become changed immediately. `sent` includes the row without requiring Add, while `edited` and `reverted` clear it with the field. A rejected save keeps the row and its validation; `rebase` clears it once the stored value matches the whole submitted field. Navigation keeps it in `settingsStore`, and reloading drops it.

`TableDraft` supplies the draft to `RowsTable` and `ListTable`. Incomplete rows and duplicate keys block submission; leaving the adding row or pressing Save marks its missing cells with the existing field-error style. Whitespace is trimmed on submission. Add and Enter still append a row and clear the adding cells (Ctrl/Command+Enter in multiline cells). Source windows also validate pending rows in their other tabs and open the tab holding the error. The project wizard keeps its table input with its other fields and includes it in both checking and adding. A milestone mode uses the pending value too; explicitly changing the mode or restoring inheritance applies to that whole value.

### Choosing a provider

The Agent section in project settings → Sessions and shared settings → Providers and models uses `ProviderChoices`: one block per offered provider, with its model and account (also execution and CLI version in shared settings). The block or its corner radio selects the default provider; editing its fields, opening help or picking a portalled account option does not. The selected block has an accent edge, tinted surface, accent title and filled check. The Provider caption holds its help, project inheritance and draft/error notes. Selecting the provider the saved value already runs restores that value (`pickedProvider`): picking back an inherited one keeps the project "as shared", with no draft. Only the selected radio is in the Tab order; arrows wrap through offered providers, Home/End select the first/last, and Space/Enter select the focused radio. Other providers' fields remain editable because run labels can select them. Below 23em of available width, fields stack inside each block.
