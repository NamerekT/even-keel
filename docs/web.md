# Page, language, config

Reference for sessions: the interface, translation, config reloading and fake states for layout work.

## Interface

- React + Vite in `web/`, built into `dist/web`, which the server serves; for client routes the server answers `index.html`.
- The client takes state types from `src/state.ts` — only types there, no `node:*`.
- `npm run dev:web` — Vite with a `/api` proxy to `EVEN_KEEL_URL` (`:4747` by default).
- Visual language (BTN-94): a plaque is either a status, `.chip`, a coloured fill (`running`, a question, a skipped task, a closed one in the stats table), or a label, `.tag`, a neutral outline (a model, "blocks"/"waits for it", the ghost's caption, "Backlog · N", tracker labels in the card). Red is only an error or a limit; mono is only task keys, code and the log. Targets are at least 24 px (WCAG 2.5.8) and the header's 44 px up to 760 px, grown with padding or an invisible `::after`, never with the text.
- Motion (BTN-112): one duration per kind of motion, the `--motion-*` tokens in `:root` of `web/src/styles.css` — `fast` 0.15 s (hover, small state changes, a caret or chevron turning, a reorder settling), `appear` 0.2 s ease-out (a page, dialog, panel or revealed section), `mark` 1.6 s ease-out (`block-glow` on a new or landed block), `skeleton` 1.4 s linear (`shimmer`), `blink` 1.2 s, `spin` 0.8 s. A new animation takes a token and an existing keyframe rather than a copy. Only the chain's beat choreography (`--beat-*` in `chain.css`) and one-off decorations (the basement, the stats stamp, the scanner) keep their own timings.
- Modal windows (BTN-114): the page behind every modal `<dialog>` — the task card, the session window, the transcript and the chat, the media viewer — is dimmed and blurred alike, by `--scrim` and `--scrim-blur` in `:root` of `web/src/styles.css`; only the media viewer keeps its own, darker dimming. A new modal takes both tokens. The chat window carries the same ↗ link to the session on claude.ai as the session panel, while the session has one.
- The task card (`web/src/pages/TaskCard.tsx`, loaded lazily together with `react-markdown`): a task title in the chain and in the backlog opens it, while the number still opens the session panel. An open card is the `?task=<id>` parameter in the address, so "back" on a phone closes it; links to other tasks inside the card replace the parameter without piling up history. Markdown links leading inside the tracker are text, and those with a task number open its card. HTML inside Markdown is rendered through `rehype-raw` and cleaned by `rehype-sanitize`: Huly writes its tables as HTML. The layout is two columns — the description and comments on the left, a panel with "Move to Todo", priority, milestone, parent, labels and relations on the right (on top below 900 px); a question or excluding label is a callout above the description. Attachments are tiles in that panel between the facts and the relations (`Attachments.tsx`): only photos and videos open, in `MediaViewer.tsx` over the whole window (arrows, ←/→, swipe, a click on a picture zooms, Esc goes back to the card), any other file downloads. A picture tile is the full file loaded lazily; a video tile has no preview on purpose — without `Range` support even `preload=metadata` could pull the whole video.
- Folding on the project page (`web/src/pages/ChainList.tsx`): the divider line itself is the button. A hidden milestone is a dashed line that reveals it; the header of a revealed one folds it together with those after it; the archive has a line that loads the next page and a line that folds it. Milestones up to the first one with open tasks cannot be folded (`fixed` in `web/src/ui/milestones.ts`); a chain without milestones has no lines at all, except the archive's.
- A backlog task on its way into the chain (`web/src/pages/useArrival.ts`): while its "Move to Todo" button is pointed at (for 250 ms, so a pointer passing over the buttons does not shake the chain) or pressed, a ghost block stands where it would land (`ProjectOrder.landing` from the service, `landingIndex` puts it ahead of the locked blockers of the task it precedes) and the page scrolls to it, revealing a folded milestone; the ghost, in the size of the tier it will take, and a milestone it unfolds grow open and fold shut by height instead of appearing at once; once the task is in the chain a copy of the backlog row flies to its block (`Flight.tsx`) and the block is marked for a moment. On a narrow screen (≤760 px) and with reduced motion there is no flight: the narrow screen closes the panel instead.
- The look of a chain block beyond its lamp (`web/src/ui/look.ts`, `web/src/pages/chain.css`): the current task is a two-line lead card with the session's last action (`showsAction`: any other task's session shows it too while mid-turn, as when the chain is stopped under a working session), the next three are full rows, the rest and the closed ones are compact; the number's shape is the priority (high — filled, medium — ring, low — faded, urgent — a red beacon plus hazard tape on the left edge, the current task — ▶); "Rework" hatches the row, a question cuts the corner; a 2 px bar along the bottom is the estimate on a log scale up to 4 h; subtasks of one parent are tied by a coloured rail left of the rows, dotted through the tasks between them, up to three lanes. A second legend line lists only the shapes the chain has.
- Links of a task (`taskLinks` in `web/src/state.ts`, `web/src/ui/Links.tsx`): every chain block and backlog row ends with two counters, a lock for the open tasks it waits for and a key for the open ones waiting for it, 0 included so the column stays in place; a pointed counter lists them in a popover (top layer, so the scrolling panel does not clip it), and a task there opens its card. A live session's plate holds the cache and context on top and, under a line, the account filling its cell with its colour and the checkpoint handoffs, 0 included. A backlog row shows priority bars, the key with the icon button "Move to Todo" left of the whole row, the milestone and the counters.
- Motion of changes (`web/src/ui/motion.ts`, `web/src/pages/useChainMotion.ts`): data on the page changes at once; the motion only marks the change and plays only while the page is visible (`visibilityState`). The page keeps the last frame the user saw per project (in memory, across page switches) and on return plays the net change since it: a task that came and went out of sight is not shown. Beats go in turn, 0.4 s apart: a finished task gets a check, a leaving one folds away (a closed one up into the archive line, whose count bumps; the copy slides under the milestone line, which has the page's background), new ones unfold, the taken one gets its frame drawn around and its lamp and ▶ light up. The taken block also grows into the lead tier only on its own beat (its size, background, title and action screen wait for `--beat-take`) and types its action once the frame is drawn (`delay` of `ActionScreen`/`Typed`), so it does not look current before the previous task has closed. A change that comes mid-motion plays alongside it (`stageOf`): running marks and leaving copies live to their own end, a block can carry marks of several motions, each mark with its own delay (`--beat-enter`, `--beat-finish`, `--beat-take`). More than five entries and exits at once — no beats: a line "While you were away: …" for 6 s that unfolds and folds back by height, so the list slides rather than jumps, and a soft glow on the new tasks. A task arriving from the backlog keeps its own flight. With reduced motion nothing moves and no leaving copies are drawn.
- From 1200 px the project page always keeps the side column, so the chain does not change width when a panel opens; with no panel open it holds `IdlePanel` — an ASCII sailboat (`web/src/ui/voyage.ts`), a meme and a hint. Below 1200 px nothing is reserved and `IdlePanel` is not mounted at all (`useWide`), so its loops do not run unseen; in a hidden tab the boat's interval stops (`useVisible`), the meme's `requestAnimationFrame` is paused by the browser itself. Arriving at a project page with an empty hash opens the session panel of the chain's current task (`focusOnEntry` in `web/src/ui/focus.ts`): the hash is set with `replace`, so "back" still leaves the page, and only once per arrival — a mount or another project key — so the cross keeps the panel closed. The boat is left for a project without a current session. Up to 760 px, where the panel covers the whole window, nothing opens by itself.
- The questions chip (`web/src/ui/QuestionsChip.tsx`) and the home page's line about questions are links built by `questionPath` (`web/src/state.ts`): to `/p/<KEY>#<ID>` of the first open question that has a session (`hasSession`: one that ran or is starting, and the task is not held back) — projects in page order, tasks in chain order — and to `/p/<KEY>` while no question has one. On the project page the chip is a link only when it has a session to open.
- The meme (`web/src/ui/memes.ts`): `momentsOf` reads the page's situation — no open tasks, empty backlog, chain stopped, running, unattended or waiting out a limit, a task on its 3rd session, a checkpoint handoff, over $1000 in the strip's 30 days — and half the draws take one of these moments' lines (`t.project.idle.moments`); the rest take a general line (`t.project.idle.memes`), `drive`, the one line that switches the boat to the old picture crawling on wheels over the swell as over land, or a play (`PLAYS`, `t.project.idle.plays`): a story in acts, each typed, held 7 s and erased like a general line before the next. `spoons` is plain nonsense and goes back to the draws after its last act. `picture` moves the voyage its own way (`playMotion`): on "Now I have the full picture" the sea and the boat stop as "Full." starts and the cloud once "Picture." is typed, two more acts try to fix it with everything still, and the last act runs the whole voyage backwards (ticks go below zero) and stays for good — no line is drawn after it until the panel is mounted again. A chat (`CHATS`, `t.project.idle.chats`) is a dialogue in the look of Claude Code, only on this panel: the human's `>` lines appear whole and muted in mono, the agent's `●` lines are typed, 1.5 s apart (`chatAt`); the lines pile up, all of them laid out from the start so the panel keeps its height, and 7 s after the last one the chat is not backspaced but selected, a line per 0.15 s from the bottom, held selected 0.7 s and deleted at once (`CHAT_SELECT`). Chats are short enough not to need scrolling, so there is none. The line is typed in parts like the home page's (1.5 s between parts) and erased at the same pace before the next one, which `pickMeme` never draws equal to the last: a general line goes 7 s after it is typed, the drive and a moment's line stay until the set of moments changes, but no less than those 7 s (the moments change as the page loads, too). The line is as wide as the picture and starts at its left edge, so lines of different length do not shift. With reduced motion the line is shown whole and only the event-driven ones change. The boat's hull never tilts — a two-row hull breaks into steps in ASCII; only the rig leans with the swell and the sway.
- The home page has memes too (`web/src/ui/memes.ts`). Under the title, `harborMemes` builds lines from the user's own numbers — the busiest of the 14 days from 50 launches, a project with ¾ of at least 50 launches, 3+ open questions, the five-hour limit from 50 % — plus the line about Even Keel itself; one draw per visit picks among them, and the numbers follow the state. A card with no task to show says why through `emptyCard`: everything done, a project with no tasks, or an empty chain with a backlog; open tasks that are only held back keep the plain "No open tasks". A card's line stands still, so several cards do not type at once: a quote in the project's colour, the first part muted as the setup and the rest in full ink as the punchline. The line under the title, in the main font, is an array of parts typed by `Typed` (`web/src/ui/Typed.tsx`) with a 3 s hold between parts; it types once per mount, a changed number in it is taken over without retyping, and with reduced motion it is shown whole. It queues up like the chains do (`Typists`, `book`): as many lines type at once as `parallel`.
- `/stats` and `/tools` end with a basement (`web/src/layout/Basement.tsx`; the page renders it, a portal puts it into `BasementSlot` below `main`, so it spans the whole window; it comes once the page's data has answered and stays through filter changes): a wall, a floor in perspective, six caution tapes at three depths — some torn with the pieces hanging and swaying, some worn — and a sign on legs with the page's line (`t.basement`). The tapes are a fixed layout, not random; with reduced motion the pieces do not sway.
- The 404 (an unknown route or a project not in the config) is the whole page as a basement: `tall` makes the scene take the rest of the window, `idle` turns the "work in progress" tape into bare stripes (nothing is being built there), and the sign carries `t.notFound` with the link up. The home and project pages get no basement: they are opened many times a day and have jokes of their own.
- While none of the chosen projects has answered, `/tools` shows the outline of the matrix (`web/src/tools/ToolsLoading.tsx`): the real section titles and project columns, a lamp per project (blue — reading, green — answered), pulsing bars and a barcode scanner by the caption. It comes after 0.15 s, so a fast answer does not flash it; with reduced motion nothing moves.
- The tab badge (`web/src/layout/tabBadge.ts`): a red dot — the status panel has an error (including a lost connection to the service), a yellow one — sessions are waiting for a reply; their count is in the title, `(2) Even Keel`. The badge without a dot is `web/public/favicon.svg`, and the dot is drawn onto it in a data URL.
- The content column is `--column` in `web/src/styles.css`: 94 % of the window, the header and the banners use the same variable.
- On a narrow screen (≤760 px, `useNarrow`) the header is one row: the brand with the project key, the waiting count and a burger (`web/src/layout/Menu.tsx`) whose dot is the worst of the status panel and the account. The burger's sheet holds the links, the chain, account and status toggles, whose panels unfold inside the sheet, and the full limits. The limits themselves stay in the header as two 2 px bars along its bottom edge, 5 hours on the left and the week on the right.
- What the page is busy with: every request except polling goes through `activity.track` (`web/src/live/activity.ts`) and shows the bar at the top of the window (`ActivityBar`). `useCommand` marks the pressed button `aria-busy` for the duration of its command, so a new command button needs nothing for its spinner. A command the service accepts at once and carries out later (`chain/restart`) keeps its button busy with `useHold` until the state changes; a block that reloads with its previous data on screen sets `aria-busy` on itself and is dimmed.
- A session that is starting (`sessionStart` in `web/src/state.ts`, `web/src/ui/SessionStart.tsx`): the current task's row shows a pill with the phase and the time since the start began, the row shimmers and its lamp is a blinking ring; the session panel shows a loading card with three steps instead of the session's facts. The phases: `launch` and `handover` while `CurrentTask.starting` is set (the dispatcher is preparing the worktree or handing over), `boot` while the page does not see the new session id yet, `answer` while that session works and its context is still empty (its feed is shown under the card). The time counts from the journal row of the new session; after 5 minutes the page stops calling it a start.
- The session's facts (`SessionBody` in `web/src/pages/SessionPanel.tsx`, styles in `web/src/pages/facts.css`) are quiet until they need attention: Time, Cache, Context and Tokens are small muted figures, and only the session state is always loud. A tile turns loud by a tone class, `panel__fact--warn` or `panel__fact--danger`: Context from the `warn` and `danger` thresholds of the scale (`contextFill`), Cache in the last fifth of its lifetime and once it is cold (`cacheTone`; a finished session stays quiet), Time and Tokens never. Tokens are one total; the split by kind is a tip opened by pointing at the number or pressing it (`web/src/ui/useTip.ts`, the same tip as the chain blocks' counters). In the window of a past session every fact is quiet.
- The chat with the current session (BTN-101; invariant 1, exception 6). The session panel of the chain's current task has a "Chat" button instead of "Open"; it is amber (`panel__chat--waiting`, the colour of `--lamp-waiting`) while the session waits for a reply. The claude.ai link is the `↗` icon `.panel__remote` in the panel head. "Whole transcript" under Activity stays only where there is no chat: past sessions (`SessionWindow`) and blocks other than the current one — writing to a past session would fork the work. The chat is `TranscriptWindow` with a `chat` target: the user's answers are right-aligned bubbles, an answered `AskUserQuestion` is a read-only card (`AskCard` in `web/src/pages/AskPanel.tsx`: the chosen options ✓ green, the rest dimmed), and the card of the open question is hidden there because the bottom shows it as `AskPanel` — tabs by `header` with ✓ once answered, radio buttons or checkboxes (`multiSelect`), an "Other" text field, a `preview` as a mono block beside the options, auto-advance on a single pick, "Send" disabled until every question has an answer. A question asked in plain text gets `ChatComposer`: text, files and "Send" (Ctrl+Enter). Both are locked with a hint why unless `lamp === 'waiting'` and the session waits on no startup dialog (`waitingFor` is `null` or it is asking); after sending they stay locked (`useHold`, 90 s or until the lamp or the open question changes). While the fix session of a red main leads the chain (BTN-119), the task the chain takes next keeps the "Chat" button for its live session (`ChainBlock.aside`, `chainBlocks`), not amber, and the chat is locked with the hint that the reply waits for the fix: `Dispatcher.answerable` takes answers only for the current task, and the session is not answered from the page before the chain is back to it. A sent answer shows at once as an optimistic line, kept until a prompt or answer line appears after it in the transcript. Styles are in `web/src/pages/ask.css`.
- `POST /api/session/answer` takes `{project, task, sessionId, ask, answers, text, files: [{name, data}]}`: `ask` is the open question's `tool_use` id or `null` for a plain-text question, `answers` maps the question text to the answer (labels joined with `, ` for `multiSelect`, the Other text as is), `data` is base64. The route alone accepts a body up to 64 MB. Refusals are the codes of `Dispatcher.answerable` (`docs/chain.md`).
- The page installs as an app (`web/public/manifest.webmanifest`, `icon-*.png` icons are renders of `favicon.svg`, the `maskable` one has the mark with a margin for cropping). There is no service worker: the service serves a fresh `dist/web` anyway. The install button in Chrome appears only in a secure context: `localhost` or HTTPS; not on a bare `http://<IP>`.

## Language (BTN-57, `src/language.ts`: `en`, `ru`)

- `language` in `even-keel.config.json` is the page language (`null` or no key — the browser language, English if it is unfamiliar), `promptLanguage` is the language of session prompts (absent — `language`, then English; `src/chain/prompts.ts`).
- The page translates its own chrome (`web/src/i18n/`, `ru.ts` is the source of the type, `en.ts` equals it) and server messages (BTN-62): pause reasons, cleanup, config, sign-in and command errors arrive as a code with values (`{ code, params, detail, cause, items }`, `src/notice/notice.ts`); the English text and the list of codes are in `src/notice/en.ts`, the Russian in `web/src/i18n/notices-ru.ts`, and the page builds the text with `say()`. A new code is an entry in both files; the type checks that the sets are equal.
- The service log is in English; git and CLI output (`detail`) and strings saved before BTN-62 (the old `state/chain.json`) are shown as is. Data (transcripts, labels, tasks) is not translated.

## Live config (`src/config-file.ts`)

The service rereads `even-keel.config.json` on the fly: `parallel`, `chain`, `brief`, a project's `prompt`, `commands` and `ci`, `model`, `modelPrompts`, `stats`, `language`, `promptLanguage` and `hiddenSkills` apply immediately, while `host`, `port`, `projects`, `context`, `tracker` apply after a restart (the log says what is waiting). A broken file — the last valid one keeps working, the error goes to the log and to a banner on the page (`ConfigBanner`).

Project settings (BTN-97): the "Settings" tag in the project head opens a side panel at `#settings` (`web/src/pages/SettingsPanel.tsx`) with the project's `prompt`, `commands.beforeStart` (one command per line) and `ci` (BTN-103: a checkbox per CI kind and "wait no longer than, min", empty — `null`) and the `fillMilestone` checkbox (BTN-107) from `EvenKeelState.settings`. "Save" sends `POST /api/project/settings` with `{project, prompt, beforeStart, check, ci, fillMilestone}` — the server refuses a body without a valid `ci` or a boolean `fillMilestone`; `ConfigFile.saveProject` reads the file, replaces only those keys in the project's entry (`ci` is written only when it is not the default) (a string entry becomes `{ repo }`, an empty value removes its key, an empty `commands` goes away), parses the whole result with `parseConfig` and writes it with a 2-space indent only if it parses, then reloads. Other keys and their values stay; comments are impossible in JSON anyway. `commands` is an object so that commands after the agent's work get a key of their own; an unknown key in it is a config error.

## Motion frame sheets (BTN-95)

An animation is checked by eye on one sheet of captioned frames, not frame by frame. Everything runs in one `browser_run_code_unsafe` call, without new dependencies.

- The state comes from `npm run dev:fake` (the table above), in the dark theme. For motion that a page timer starts (`?chain=close`), `page.clock.install()` goes before `goto` and `page.clock.runFor(ms)` moves time on: the page's timers then stand still and do not clear the marks while frames are taken.
- CSS animations and transitions: once the motion has started, `document.getAnimations().forEach((a) => a.pause())`, then for each moment set `a.currentTime = t` on all of them — one clock for the whole motion, `--beat` delays included. Moments: the start, quarters, the end, keyframe peaks.
- JS motion (`Typed`, `IdlePanel`, `Flight`): a series at an even step of 50–100 ms from its start.
- Each frame is captioned with its time from the start in ms and, per animation, `animationName` (`transitionProperty` for a transition, the beat or the text for JS) and `getComputedTiming().progress` in %.
- A frame is a `page.screenshot({ clip })` around the element, not the whole screen. The sheet is a new page (`page.context().newPage()`) with a grid of `img` from data URLs and their captions, taken with one `screenshot({ fullPage: true })` into `.temp/motion/<animation>/sheet.png`.
- Reduced motion: `page.emulateMedia({ reducedMotion: 'reduce' })`, then the `getAnimations()` with `playState === 'running'` — each one left has a reason (a loader slowed to 3 s) or is a defect.
