# Page, language, config

Reference for sessions: the interface, translation, config reloading and fake states for layout work.

## Interface

- React + Vite in `web/`, built into `dist/web`, which the server serves; for client routes the server answers `index.html`.
- The client takes state types from `src/state.ts` — only types there, no `node:*`.
- A project page is `/p/<id>`, the project's GUID (BTN-132): links are built by `projectPath(project)` and the route is read back by `projectOfPath(state, param)` (`web/src/state.ts`). An older `/p/<KEY>` link is replaced by the id route of the first project of the key, with its search and hash (`ProjectRoute` in `web/src/App.tsx`).
- The state names every project by its id, as the service does (BTN-271): `projects`, the chain, every per-project map and `tasks` (each with its `project`, since two projects may read one tracker project). `projectKeys` gives the key (stats, old links, the fix name), `taskPrefixes` the prefix of the task ids, `projectLabels` what to show: the key, with a distinguisher where another project has it (`projectLabel` in `src/config.ts`, `useProjectLabel`/`ProjectLabel` in `web/src/ui/ProjectLabel.tsx`). A task's project is `taskProject(state, task)`. Server notices that name a project by id are shown by its label: `say()` runs `withLabels` (`src/notice/notice.ts`) with the labels `App` sets (`setProjectLabels`), and the service log does the same to every line. Where the page's text names another project it is a link to its page (BTN-319): `ProjectLinks` (`web/src/ui/ProjectLinks.tsx`) takes a text with the projects by their ids — `sayIds()` of a notice (`<Said>`), or a page text given ids — and makes each one a link by its label, the page's own project staying text; an id inside a task id (`ABC-5`) is not taken (`piecesOf`). It is used on the plaques of the project page and the card (the chain's error, a slot, CI or release-carry wait, cleanup warnings), the packages banner and the event and update toasts; the launch chart's legend links its projects too. A link inside a card stands above the card's stretched link (`.project-link`), and a toast with an `href` must not get one in its title. A project card selects no text: a press anywhere on it but its buttons and links opens the project, the task title cut short too — it stands above the stretched link for its tip, so it is a link to the project itself (`TaskTitle` in `ProjectCard.tsx`).
- When `src/main.ts` could not migrate the storage, the service serves only the page: `/api/events` sends one `blocked` event with the reason (`LiveSnapshot.blocked`), and the page shows nothing but the error banner `app.blocked` (`docs/chain.md`, "State files and the schema version").
- `npm run dev:web` — Vite with a `/api` proxy to `EVEN_KEEL_URL` (`:4747` by default).
- How the page looks — tokens, blocks, layout, the plaques, tips, motion, modals and the check before a merge — is `docs/design.md`.
- The chat window carries the same ↗ link to the session on claude.ai as the session panel, while the session has one.
- The task card (`web/src/pages/TaskCard.tsx`, loaded lazily together with `react-markdown`): a task title in the backlog, in the session panel's head and of a locked blocker in the chain opens it; a press anywhere else on a chain row (all but its links and the meters on the right) opens the session panel, the key's link stretched over the row. An open card is the `?task=<id>` parameter in the address, so "back" on a phone closes it; links to other tasks inside the card replace the parameter without piling up history. Markdown links leading inside the tracker are text, and those with a task number open its card. HTML inside Markdown is rendered through `rehype-raw` and cleaned by `rehype-sanitize`: Huly writes its tables as HTML. The layout is two columns — the description and comments on the left, a panel with "Move to Todo", priority, milestone, parent, labels and relations on the right (on top below 900 px); where the tracker has `milestones`/`moveMilestone` (`docs/trackers.md`) the milestone is a `Select` that moves the task at once, without a confirmation: the new value shows right away and goes back with the error if the tracker refuses; a question or excluding label is a callout above the description. Attachments are tiles in that panel between the facts and the relations (`Attachments.tsx`): only photos and videos open, in `MediaViewer.tsx` over the whole window (arrows, ←/→, swipe, a click on a picture zooms, Esc goes back to the card), any other file downloads. A picture tile is the full file loaded lazily; a video tile has no preview on purpose — without `Range` support even `preload=metadata` could pull the whole video.
- A modal closes from its backdrop only when the left button went both down and up on it (EKR-23, `useBackdropClose` in `web/src/ui/backdrop.ts`): a `click` goes to the common ancestor of the press and the release, the `<dialog>` itself, so a text selection dragged out of the window used to close it. A press on the backdrop does not start a selection. Every modal but the sign-in, which does not close from its backdrop at all, uses it; the media viewer counts its stage as backdrop too.
- The changelog of a milestone (BTN-142, BTN-209, `web/src/pages/ChangelogDialog.tsx`): a milestone head of the chain — not "no milestone", not the archive — ends with a sheet-and-pen button (its tip says what it is) and, once the milestone's section has been written to the file, "+N since written": the done tasks of the milestone in `state.tasks` that the last written version does not account for (`state.changelogs`, counted by the page in `web/src/changelog.ts`). The button opens a modal that asks `changelog/open` at once: the newest version kept in the database comes back right away, otherwise the agent writes one (a minute or two, "writing" in the body). The section is shown line by line against the version's `base` (`diffSection`, `src/changelog/diff.ts`): added lines green, removed ones struck through on red, a line with a few words replaced shows those words; the first version is compared with the file's section, so the user's own edits are not marked as the agent's. Above it — how many done tasks the version accounts for and how many are open, the user's words of an edit, the tag a released milestone has. Under it — a box "what to change": Enter sends `changelog/edit` with the words, Shift+Enter is a new line. The foot: the version's number and time, or the file and the short commit it was written by ("already in" when the file had the text), then what the version's turn cost (its tokens when the agent counts no cost) and, past one turn, "… in all" for every version of the milestone (`ChangelogView.spent`); pointed at, the account folder, the model, the time, the tokens by kind, whether it came out of the account's limits or its API key's credit, and that `/stats` does not count these turns; "Add N" (`changelog/add`, only when N done tasks are not in the version); "Write again" (`changelog/again`); "Copy" (the clipboard API, else a hidden field inside the dialog and `execCommand('copy')` — plain HTTP from another host has no clipboard API); "Write" (`changelog/write`, primary, greyed once written). The server side and the freeze of a released section are in `docs/releases.md`. An error stays in the modal (`changelog.*` codes). Where the tracker lacks `milestoneTasks` or the agent lacks `write` the button still shows and the modal says so (`docs/sessions.md`, "One-off turns").
- The project head (`web/src/pages/Project.tsx`, `project.css`): the key, the display name, the questions chip and the tracker read on the left. The tracker read (`TrackerRead`) is a refresh icon that reads the project's tasks now (`POST /api/chain/refresh` with `{project}`; the icon spins while it runs) and "updated N ago" from `trackers[].readAt[<key>]`, the time of the project's last successful read; the poll is every 30 s, the button is for a change made in the tracker a moment ago. The name is the config's `projects[].name` (`projectName` in `web/src/state.ts`); `ProjectName.tsx` edits it in place — a click turns it into an input, Enter or leaving it saves through `project/settings`, Escape cancels. Everywhere else a project is named by `web/src/ui/ProjectLabel.tsx` — the key, then the name when there is one: the header's crumb, the account menu, the queue panel, the home card, the launch chart's legend; the chain status right before the buttons that change it, and why a button is off is that button's `title`, not a line. The CI badge, "Backlog · N" and "Settings" are tabs over the side column (`.side-tabs`), one strip with dividers: CI a narrow one, the other two share the rest; the strip is flat at the bottom and stands on the card under it, whose top corners are square; each opens its own card (`#ci`, `#backlog`, `#settings`), and the open one takes the card's background. From 761 px the card's frame does not animate, only its content fades in (`fade-in`); up to 760 px the panel still slides in. With no side column (under 1200 px with no panel open) the three end the head row as the chip and the tags. Up to 760 px the head is built from the header's blocks (`.hblock`, the `look` of `chipLook.ts`): the three are one block of segments at the end of the title row — CI with its dot, the backlog's icon and count, the settings' icon — and the next row is the status with the two chain buttons as one block, the primary one filled.
- Folding on the project page (`web/src/pages/ChainList.tsx`): the divider line itself is the button. A hidden milestone is a dashed line that reveals it; the header of a revealed one folds it together with those after it. The archive is one line above the chain: folded, a dashed line with the count that opens the latest page; open, a block of its own (`archiveView` gives its pages apart from the chain, `archived`) — the line "N of M" with "K more" for the next, older page and a press on the line folding it all, and under it the closed tasks as quiet one-line rows (`ArchivedRow`: lamp, key, title, the milestone only where it changes) in the columns of the chain's rows, never inside the milestone sections. The last closed task stays a row of the chain. Milestones up to the first one with open tasks cannot be folded (`fixed` in `web/src/ui/milestones.ts`); a chain without milestones has no lines at all, except the archive's.
- A backlog task on its way into the chain (`web/src/pages/useArrival.ts`): while its "Move to Todo" button is pointed at (for 250 ms, so a pointer passing over the buttons does not shake the chain) or pressed, a ghost block stands where it would land (`ProjectOrder.landing` from the service, `landingIndex` puts it ahead of the locked blockers of the task it precedes) and the page scrolls to it, revealing a folded milestone; the ghost, in the size of the tier it will take, and a milestone it unfolds grow open and fold shut by height instead of appearing at once. On the press the backlog row slides straight left out of the panel, fading, and folds (`.backlog__row--leaving`; the panel keeps a copy of it until then, should the chain take the task sooner); once it has gone and the task is in the chain, a copy enters at the height of its block from behind the side column (`.flight` stands under `.project__side`) and slides straight left onto it, fading in, so it does not pop up out of nowhere when the column is closed or another card is opened meanwhile (`Flight.tsx`); then the block is marked for a moment. On a narrow screen (≤760 px) and with reduced motion there is no flight: the narrow screen closes the panel instead.
- The lamp of a task (`taskLamp` in `web/src/state.ts`) is one for every place the task shows — the chain block, the home card, the queue, the blockers list: the tracker status first (done, canceled), then the session; with no session a task in the backlog (status category `UnStarted`) is `backlog` (dotted ring), not `ahead`, so a blocker the chain does not show reads as waiting in the backlog. A finished session of an open task is `stopped` (amber ring), not done; a session whose last line is `CHECKPOINT: …` (`SessionView.checkpoint`) is `handoff` (half-filled blue) whether its process lives or not, and it does not count as waiting for a reply. A background job that `claude agents` still calls `working` but has no live process 5 min after its launch is finished (`lampOf` in `src/sessions/agents.ts`).
- The look of a chain block beyond its lamp (`web/src/ui/look.ts`, `web/src/pages/chain.css`): the current task is a two-line lead card with the session's last action (`showsAction`: any other task's session shows it too while mid-turn, as when the chain is stopped under a working session), the next three are full rows, the rest and the closed ones are compact; the number's shape is the priority (high — filled, medium — ring, low — faded, urgent — a red beacon plus hazard tape on the left edge, the current task — ▶); "Rework" hatches the row, a question cuts the corner; a 2 px bar along the bottom is the estimate on a log scale up to 4 h; subtasks of one parent are tied by a coloured rail left of the rows, dotted through the tasks between them, up to three lanes. A second legend line lists only the shapes the chain has.
- Links of a task (`taskLinks` in `web/src/state.ts`, `web/src/ui/Links.tsx`): every chain block and backlog row ends with two counters, a lock for the open tasks it waits for and a key for the open ones waiting for it, 0 included so the column stays in place; a pointed counter lists them in a popover (top layer, so the scrolling panel does not clip it), and a task there opens its card. A live session's metrics (`web/src/ui/BlockMetrics.tsx`, BTN-299, BTN-331), each part with its figures in a `Tipped` tip: the cache as a ring that drains to cold (`cacheShare`; green, amber in its last fifth, a dashed grey ring once cold), the context with its percent (blue, amber, red by the `context` thresholds), the account's initial in its colour only when the session runs on an account other than the project's (`foreignAccount` in `web/src/accounts.ts`: no folder with that e-mail lists the project in `AccountEntry.projects`), and the context resets, hidden at 0. The resets (`contextResets` in `web/src/state.ts`) count every new session with a handoff — checkpoint, limit, another cause of a `relay`, a restart by hand — and every compaction of the task's sessions; the tip and the head of the card's session list break them down, and a session's row in that list adds its compactions. Compactions come from the transcripts the monitor follows (`TranscriptSummary.compactions`: Claude's `compact_boundary`, Codex's `compacted` line, `docs/unverified.md`), kept per session in memory (`SessionMonitor.compactionsOf`) and put on `TaskSession.compactions` when there are any, so a session gone from the agents' list before the service started shows none. A row whose session opens its second line (`showsAction`: working, and the lead's also on an error or a limit) gives the title the whole first line and puts `ActionMeter` under it, as wide as the title and the side: the current action (`ActionScreen`, an empty prompt while there is none) on a field filled to the context level with a hard edge (`--fill`, registered so a new level slides), then the initial, the resets and the percent; it opens with `action-open` as one piece. Any other metered row stays one line with the metrics as a plate (`BlockMetrics`) before the links; a later chip of the row goes on its end. The cache ring takes the number's place when the row is current (instead of the former ▶, kept only while there is no cache) or has no number, and the plate's ring otherwise. A backlog row shows priority bars, the key with the icon button "Move to Todo" left of the whole row, the milestone and the counters.
- Motion of changes (`web/src/ui/motion.ts`, `web/src/pages/useChainMotion.ts`): data on the page changes at once; the motion only marks the change and plays only while the page is visible (`visibilityState`). The page keeps the last frame the user saw per project (in memory, across page switches) and on return plays the net change since it: a task that came and went out of sight is not shown. Beats go in turn, 0.4 s apart: a finished task gets a check, a leaving one folds away (a closed one up into the archive line, whose count bumps; the copy slides under the milestone line, which has the page's background), new ones unfold, the taken one gets its frame drawn around and its lamp and cache ring (or ▶) light up. The taken block also grows into the lead tier only on its own beat (its size, background, title and action field wait for `--beat-take`) and types its action once the frame is drawn (`delay` of `ActionScreen`/`Typed`), so it does not look current before the previous task has closed. A change that comes mid-motion plays alongside it (`stageOf`): running marks and leaving copies live to their own end, a block can carry marks of several motions, each mark with its own delay (`--beat-enter`, `--beat-finish`, `--beat-take`). More than five entries and exits at once — no beats: a line "While you were away: …" for 6 s that unfolds and folds back by height, so the list slides rather than jumps, and a soft glow on the new tasks. A task arriving from the backlog keeps its own flight. With reduced motion nothing moves and no leaving copies are drawn.
- From 1200 px the project page always keeps the side column, so the chain does not change width when a panel opens; with no panel open it holds `IdlePanel` — an ASCII sailboat (`web/src/ui/voyage.ts`), a meme and a hint. Below 1200 px nothing is reserved and `IdlePanel` is not mounted at all (`useWide`), so its loops do not run unseen; in a hidden tab the boat's interval stops (`useVisible`), the meme's `requestAnimationFrame` is paused by the browser itself. Arriving at a project page with an empty hash opens the session panel of the chain's current task (`focusOnEntry` in `web/src/ui/focus.ts`): the hash is set with `replace`, so "back" still leaves the page, and only once per arrival — a mount or another project key — so the cross keeps the panel closed. The boat is left for a project without a current session. Up to 760 px, where the panel covers the whole window, nothing opens by itself.
- The questions chip (`web/src/ui/QuestionsChip.tsx`) and the home page's line about questions are links built by `questionPath` (`web/src/state.ts`): to `/p/<id>#<ID>` of the first open question that has a session (`hasSession`: one that ran or is starting, and the task is not held back) — projects in page order, tasks in chain order — and to `/p/<id>` while no question has one. On the project page the chip is a link only when it has a session to open.
- The meme (`web/src/ui/memes.ts`): `momentsOf` reads the page's situation — no open tasks, empty backlog, chain stopped, running, unattended or waiting out a limit, a task on its 3rd session, a checkpoint handoff, over $1000 in the strip's 30 days — and a quarter of the draws take one of these moments' lines (a moment holds as long as the page stands still, so a bigger share made it a refrain) (`t.project.idle.moments`); the rest take a general line (`t.project.idle.memes`), `drive`, the one line that switches the boat to the old picture crawling on wheels over a hill as over land, or a play (`PLAYS`, `t.project.idle.plays`): a story in acts, each typed, held 7 s and erased like a general line before the next. `spoons` is plain nonsense and goes back to the draws after its last act. `picture` moves the voyage its own way (`playMotion`): on "Now I have the full picture" the sea and the boat stop as "Full." starts and the sky (clouds and gulls) once "Picture." is typed, two more acts try to fix it with everything still, and the last act runs the whole voyage backwards (ticks go below zero) and stays for good — no line is drawn after it until the panel is mounted again. A chat (`CHATS`, `t.project.idle.chats`) is a dialogue in the look of Claude Code, only on this panel: the human's `>` lines appear whole and muted in mono, the agent's `●` lines are typed, 1.5 s apart (`chatAt`); the lines pile up, all of them laid out from the start so the panel keeps its height, and 7 s after the last one the chat is not backspaced but selected, a line per 0.15 s from the bottom, held selected 0.7 s and deleted at once (`CHAT_SELECT`). Chats are short enough not to need scrolling, so there is none. The line is typed in parts like the home page's (1.5 s between parts) and erased at the same pace before the next one, which `pickMeme` never draws equal to the last: a general line and a moment's line go 7 s after they are typed, the drive stays until the set of moments changes, but no less than those 7 s (the moments change as the page loads, too). The line is as wide as the picture and starts at its left edge, so lines of different length do not shift. With reduced motion the line is shown whole and only the event-driven ones change. The picture is set in 7px type and is as wide as the panel: `useColumns` in `IdlePanel` measures the panel on every resize and passes the column count to `voyageFrame`, so the sea and the sky stretch while the boat keeps its size. The sailing boat rides two endless trains of waves with troughs below the calm level; the water's height inside a row is drawn with `'`, `-`, `.` and `_`, so the slopes are smooth instead of row-high steps. The hull is shorter than half the main wave, and under it the water is drawn up to its bottom, so the boat never hangs over a trough between two crests. The hull never tilts — a hull breaks into steps in ASCII; only the rig leans with the waves and the sway, by a third of their slope, and it is sheared rather than turned, so the boom keeps its row.
- The home page has memes too (`web/src/ui/memes.ts`). Under the title, `harborMemes` builds lines from the user's own numbers — the busiest of the 14 days from 50 launches, a project with ¾ of at least 50 launches, 3+ open questions, the five-hour limit from 50 % — plus the line about Even Keel itself; one draw per visit picks among them, and the numbers follow the state. A project with no task to show says why through `emptyCard`: everything done, a project with no tasks, or an empty chain with a backlog — these are quiet rows, the line in their tip; open tasks that are only held back keep the plain "No open tasks" on a full card. The same three kinds add a call to file tasks or ready them in the tracker (`emptyCall`, EKR-13): under the joke in the tip, at the top of the project page in place of "No tasks in the chain", and under the joke of a card (queued, paused or with a question), with an "Open in <tracker>" button when the tracker gives the project's page (`trackerUrls.pages`, `TrackerSetup.projectUrl`) and one more for each task feed whose tracker gives its page, the project's first (`projectPages`, BTN-329); two buttons of one tracker add their keys ("Open in Huly · OPS"). In `dev:fake` XYZ is the empty project, each project's page a made-up Huly address, ABC's feeds a GitHub and a Linear one. A card's line stands still, so several cards do not type at once: a quote in the project's colour, the first part muted as the setup and the rest in full ink as the punchline. The line under the title, in the main font, is an array of parts typed by `Typed` (`web/src/ui/Typed.tsx`) with a 3 s hold between parts; it types once per mount, a changed number in it is taken over without retyping, and with reduced motion it is shown whole. It queues up like the chains do (`Typists`, `book`): as many lines type at once as `parallel`.
- The order of the home cards (BTN-207, BTN-244, `web/src/pages/homeGroups.ts`). A switch of four icons in the head (`GroupingSwitch`, kept in `localStorage` under `even-keel.home.grouping`, without groups until chosen) shows one plain grid (`none`) or groups the projects by repository, by tracker connection (`state.trackers`, titled by its `title`) or both — remote blocks, with tracker subheads inside a block only when it holds two trackers. A remote group is the projects whose checkouts share a remote, transitively; the service reads each checkout's remotes into `state.remotes` (`ProjectRemotes`, `src/projects/remotes.ts`, on a config change and every minute with the CI targets), and `remoteRef` makes one id of every url of a repository — host and path in lower case, without credentials, port, `.git` or the remote's name, a local bare repository by its resolved path. The group is titled by the `owner/repo` most of its projects share (a local one by its folder). A project left alone in its group, or without remotes, goes into one block after the groups, titled "Other". When there is at least one group, every block is a framed panel titled with its project count; otherwise the one block is the plain grid. Inside a section the full cards come working first (the chain runs, is queued or paused, or a question is open — `zoneOf`), then the rest, each in config order; the block's quiet projects (`ghost`, `finished`, `shelved`) leave the grid for one wrapping strip at its bottom (`laidOut`, `QuietRow`: colour, key, done/total, a link to the project; the name and the joke in a tip), and a tracker section left without cards drops its subhead. The punchlines' turns (`emptyTurns`) go by this page order. A card's task title is clamped to two lines, the whole of it in a tip only when cut. When every open task is held (skipped, or behind a blocker the chain does not take), the card and the queue show the first of the chain marked "Skipped" or "Blocked" (`CardTask.held`), not "No open tasks". In `dev:fake` ABC and XYZ share `john/app` (`FAKE_REMOTES`), so the page shows one group; the fake has one tracker, so "by tracker" is one group of four.
- `/stats` and `/tools` end with a basement (`web/src/layout/Basement.tsx`; the page renders it, a portal puts it into `BasementSlot` below `main`, so it spans the whole window; it comes once the page's data has answered and stays through filter changes): a wall, a floor in perspective, six caution tapes at three depths — some torn with the pieces hanging and swaying, some worn — and a sign on legs with the page's line (`t.basement`). The tapes are a fixed layout, not random; with reduced motion the pieces do not sway.
- The 404 (an unknown route or a project not in the config) is the whole page as a basement: `tall` makes the scene take the rest of the window, `idle` turns the "work in progress" tape into bare stripes (nothing is being built there), and the sign carries `t.notFound` with the link up. The home and project pages get no basement: they are opened many times a day and have jokes of their own.
- While none of the chosen projects has answered, `/tools` shows the outline of the matrix (`web/src/tools/ToolsLoading.tsx`): the real section titles and project columns, a lamp per project (blue — reading, green — answered), pulsing bars and a barcode scanner by the caption. It comes after 0.15 s, so a fast answer does not flash it; with reduced motion nothing moves.
- Updates (BTN-134, `src/updates/`): the service reads its version from `package.json` and, while `updates.check` is on, asks `api.github.com/repos/<repository>/releases?per_page=30` (no token) at start and every 12 h (`UpdateWatcher`, `releasesOf`) — not during the first run (`firstRun`, BTN-310): the setup asks whether to, and the first ask comes once the run ends (a config change calls `configChanged`); drafts, prereleases and tags that are not a version are ignored, and a failed request is one log line. The page gets `EvenKeelState.updates` (`updatesView` for the releases, `Updater.view()` for the rest): the last row of the gear menu and of the burger's sheet is "Even Keel <version>", with a button "<version> available" when a release is newer, or "back to <version>" when this version came by an update (`VersionRow` in `web/src/layout/Updates.tsx`). Both open the update window (`UpdateWindow`, BTN-163). A newer release also gets a toast in the window's corner (`UpdateToast`, built on the generic `web/src/ui/Toast.tsx`) unless `updates.notify` is off or `updates.dismissed` is that version: "Update…" opens the window, "Close" sends `updates/dismiss {version}` (a later release shows it again), "Don't show again" sends `updates/mute` (writes `notify: false`); both are written to the config, so every device stops showing it.
- The update window (BTN-163): the installed and the latest version, the notes of every release newer than the installed one (`notes`, newest first, markdown sanitized), an amber mark over a note with a `### Reverted` section (`revertedOf`: its text up to the next heading of level 3 or above), and "Update to <version>" (`updates/install`) or why there is none (`blocked`: not a service, not a git checkout, uncommitted changes, HEAD not on the installed version's tag; an npm install that is not global). The text under the button follows `source`: a checkout and a build, or an npm install. Under it the previous version (`previous`) with "Revert to <version>" (`updates/revert`) or why not — `storage` when the storage versions differ, with the way back from the `.bak` copies. An update under way is a toast (`UpdateProgressToast`, `progress`: "waiting for <projects>" while the chains settle, then "updating…"), and the page calls `location.reload()` once the service answers with another version. How it ended is a toast after the restart (`UpdateResultToast`, `result`): "Details" opens the window with the step, the rollback and the output, "Close" sends `updates/seen`. The process itself is in `docs/service.md`, "Updating from the page".
- Run label fallbacks (BTN-173): a launch whose run label named a provider without an account in the pool (`docs/sessions.md`, "Run profiles") is in `EvenKeelState.fallbacks` for 24 hours, from the launch log; each gets a toast (`FallbackToasts`, `web/src/layout/Fallbacks.tsx`) with the `chain.noAccountFor` notice. "Close" is per device: the closed ones are kept in `localStorage` (`even-keel.fallbacks.dismissed`, `<at>|<task>`).
- Unchecked CLI versions (BTN-249, `src/agent/versions.ts`): each agent adapter names the CLI version Even Keel was last checked against (`AgentAdapter.checked`, the same as the README's "Last checked against"), and the service asks the CLI each agent runs its `--version` at start, every 15 minutes and once its own copy of the checked version is downloaded (`VersionWatcher`; a failed call is one log line and keeps what was known). ## Live config (`src/config-store.ts`)

The settings are in the database since BTN-199 (`docs/storage.md`), and the service looks at them every 2 s, so a `config-import` applies on the fly too; every key with its levels and who writes it is in `docs/settings.md`. Every key applies at once (BTN-130): `ConfigStore.current` is the last valid parse, and `onChange(before)` lets the service rebuild what a key feeds (`projectsChanged` in `src/service.ts`: trackers, CI watches, packages, the chain of a renamed or removed project — `docs/chain.md`). The page has no restart marks. What still needs a restart is a few start-only environment variables (`docs/service.md`, "What applies on the fly"). `host` and `port` are not config keys any more (BTN-117): the address is `EVEN_KEEL_HOST`/`EVEN_KEEL_PORT` (`listenOf`), and an imported file that still has them gets one warning in the log. Settings that do not parse (written past the checks) — the last valid ones keep working, the error goes to the log, to a banner on the page (`ConfigBanner`) and, when its notice names a field (`fieldOf`, `web/src/pages/settingsField.ts`), under that field.

The page edits the settings; a hand edit is `config-export`, edit, `config-import`. `EvenKeelState.config` (`ConfigView`, built by `formsOf`) holds the effective values as forms — `shared: SharedForm`, `projects: Record<key, ProjectForm>` — with the trackers the form can pick (`TrackerChoice`, with the key a project names its tracker project by). Saving takes the settings in the config's format (`ConfigStore.raw()`), sets the keys of the fields the form changed (`withProjectForm`, `withSharedForm`), parses the whole result with `parseConfig` and, only if it parses, applies it and writes it into the database behind. "Changed" is against the base the save sends with the form (BTN-128): the values its draft started from, not the settings as they are now, so a field imported under an open form is not written back over (`baseOf` in `src/server.ts`, a missing base is `request.required`). A value the form did not change keeps its key as written, even if it repeats what it would inherit; a changed one is written only where it differs from what it would inherit — a project's `brief` and `chain` rules from the shared ones, a shared key from the default — otherwise its key goes; a project's `tracker` is always written, it inherits nothing (BTN-345). A project clearing `active` or `terminal` over a shared list writes `null`: back to the status categories. A string project entry becomes `{ repo }`, an empty value removes its key, an empty `commands` goes away; comments are impossible in JSON anyway. `commands` is an object so that commands after the agent's work get a key of their own; an unknown key in it is a config error.

## Screenshots (`npm run shot`)

`scripts/shot.ts` is the cheap way for a session to look at the page: a Playwright MCP step returns the page's whole accessibility tree into the context, the script returns a few lines and the PNGs of the elements asked for, read only when needed. One run is ~4 s.

```sh
npm run shot -- '?chain=ask&card=empty' .cards 'dialog[open]' --click '.card__key >> nth=0' --size 390x844
```

- The first argument starting with `?`, `/` or `#` is the route; it opens on a `dev:fake` server the script starts in-process on a free port (no port 5173, nothing left running), or on `--url <base>` (`http://localhost:4747` — the service).
- Every other argument is a selector: it is waited for (5 s), and its first match is shot alone into `.temp/shot/<name>/<n>-<selector>.png`; without selectors, the viewport into `page.png` (`--full` for the whole page). `<name>` is the route as a slug or `--name`; the folder is emptied on each run.
- Steps run in the order given, before the shots: `--click <sel>`, `--hover <sel>`, `--press <key>`, `--fill <sel>=<text>`, `--wait <sel|ms>`; then `--settle` ms (500). `--fill` splits at the first `=`, so its selector cannot hold one (`nth=1`, `[type=text]`): use `:nth-child()` or a class. A step's selector takes the first match on the whole page: a portalled dialog comes after the page, so scope it (`dialog button[type=submit]`).
- From Git Bash a route starting with `/` becomes a Windows path (`C:/Program Files/Git/tools`): run with `MSYS_NO_PATHCONV=1`, or from PowerShell.
- Dark theme, 1280×800 by default: `--light`, `--size WxH`. CSS animations are finished for the shot (`animations: 'disabled'`); motion is the frame sheet below.
- The report per selector: the match count, the box, and three lists of hints, each capped at `--limit` (8): `spill` — content wider or taller than a box with `overflow: visible` (the deepest such box), `cut` — content clipped by `hidden`/`clip`, marked when it is an ellipsis, `overlap` — in-flow siblings whose boxes cross. SVG shapes, boxes of 1 px or less and 2 px of slack are ignored. A hint is not a defect by itself (a stretched hit area spills by design): the picture decides.
- `--eval <js>` prints an expression's value from the page (a computed colour, a width); `--no-image` gives only the report.
- Exit code 1 when a selector is not found or the page logged an error (both printed), 2 when a step or the launch failed.
- The browser is only Playwright's headless shell (`npx playwright install chromium-headless-shell` after a Playwright bump). Never the installed Chrome: on Windows a fresh Chrome profile checks for a blank OS password with `LogonUser`, each launch is a failed logon (Security 4625 from `chrome.exe`), and a few runs lock the account and the service with it. The page side is `scripts/shot.page.js`, plain JS as an init script: tsx would wrap functions passed to `evaluate` in an undefined `__name`.

## Motion frame sheets (BTN-95)

An animation is checked by eye on one sheet of captioned frames, not frame by frame. Everything runs in one `browser_run_code_unsafe` call, without new dependencies.

- The state comes from `npm run dev:fake` (the table above), in the dark theme. For motion that a page timer starts (`?chain=close`), `page.clock.install()` goes before `goto` and `page.clock.runFor(ms)` moves time on: the page's timers then stand still and do not clear the marks while frames are taken.
- CSS animations and transitions: once the motion has started, `document.getAnimations().forEach((a) => a.pause())`, then for each moment set `a.currentTime = t` on all of them — one clock for the whole motion, `--beat` delays included. Moments: the start, quarters, the end, keyframe peaks.
- JS motion (`Typed`, `IdlePanel`, `Flight`): a series at an even step of 50–100 ms from its start.
- Each frame is captioned with its time from the start in ms and, per animation, `animationName` (`transitionProperty` for a transition, the beat or the text for JS) and `getComputedTiming().progress` in %.
- A frame is a `page.screenshot({ clip })` around the element, not the whole screen. The sheet is a new page (`page.context().newPage()`) with a grid of `img` from data URLs and their captions, taken with one `screenshot({ fullPage: true })` into `.temp/motion/<animation>/sheet.png`.
- Reduced motion: `page.emulateMedia({ reducedMotion: 'reduce' })`, then the `getAnimations()` with `playState === 'running'` — each one left has a reason (a loader slowed to 3 s) or is a defect.
