# Sessions: GitHub Copilot

## GitHub Copilot (BTN-215, `src/copilot/`)

Built on the research below (BTN-213) and checked on Copilot CLI 1.0.98 on Windows from a terminal: a launch with `--session-id`, a resume, the transcript fold against the CLI's own `session.shutdown` totals, the Tally rows. Later chain checks covered the Windows service, macOS launchd and Linux in a Docker container ([verified](../verified/copilot.md)); the remaining service/sign-in combinations are in [unverified](../unverified/copilot.md). The binary: `EVEN_KEEL_COPILOT_BIN`, otherwise Even Keel's own copy of the checked version while `cli.copilot` is `checked` and the copy is downloaded ("The checked CLI" below, BTN-347), otherwise on Windows the `copilot.exe` winget installed (`%LOCALAPPDATA%\Microsoft\WinGet\Links`, else the package folder under `WinGet\Packages\GitHub.Copilot_*`), otherwise on Windows the native `copilot.exe` of an npm install — `node_modules\@github\copilot\node_modules\@github\copilot-win32-<arch>\` or its hoisted `node_modules\@github\copilot-win32-<arch>\` under a PATH folder or `%APPDATA%\npm` (BTN-623: the wrappers `copilot`, `copilot.cmd` on the PATH need a shell, and `findBinary` on Windows counts only `.com` and `.exe`), otherwise `copilot`; any of them with `--no-auto-update` and `COPILOT_AUTO_UPDATE=false`. A binary `spawn` cannot find pauses the chain with `copilot.binaryMissing`, which names it and sends to the CLI version setting or `EVEN_KEEL_COPILOT_BIN`.

- A turn is `copilot -C <dir> --output-format json --no-auto-update --no-ask-user --allow-all-tools (--session-id <uuid> --name <task> | --resume=<id>) [--model <model>] [--add-dir <main checkout>] [MCP flags] [--plugin-dir <dir>…] --prompt=<prompt>`, a detached process with its JSONL in a file (`TurnRegistry`, `state/copilot/`), as Codex's. Even Keel gives a new session its id, so the session is known before the first event; the prompt goes as `--prompt=`, since a reply starts with `-`. The turn is over at the `result` line, the last of `--output-format json`. Liveness, `resting` and `stop` are Codex's.
- `--no-ask-user` takes the question tool away: a question is the text a turn ends with, answered from the chat window, as with Codex. `--add-dir` lets a worktree's session merge into the main checkout; there is no `execution.copilot`, since Copilot has no OS sandbox to bypass.
- The account's environment (`copilotEnv`): `COPILOT_HOME` is the account folder, `COPILOT_GITHUB_TOKEN` its token when it has one (`GH_TOKEN` and `GITHUB_TOKEN` are removed, since the CLI would take them), `COPILOT_AUTO_UPDATE=false`. A folder without a token runs on the machine's own `copilot login` (`docs/accounts.md`).
- The transcript is `<COPILOT_HOME>/session-state/<id>/events.jsonl` (`CopilotFold`): the feed from `user.message`, `assistant.message` and its `toolRequests`, tool names mapped to Claude's (`powershell`/`bash` → `Shell`, `view` → `Read`, `edit` → `Edit`, `create` → `Write`, an MCP tool `<server>-<tool>` → `mcp__<server>__<tool>`); the context is `inputTokens` of the last main-thread `session.usage_record` (the cache included), the window its `maxPromptTokens`, the model its `model` (`auto` resolves to a real model there). A `session.error` is the API error: `rate_limit`/`quota` or a text about a limit is a limit, `billing_not_configured` or a text about billing or AI credits is spent credit.
- The MCP servers of the project's packages go through the gateway as `--additional-mcp-config`; Copilot has no strict mode, so `--disable-builtin-mcps` drops its GitHub server and `--disable-mcp-server` each server of the project's `.mcp.json`, `.github/mcp.json`, `.vscode/mcp.json`, the account's `mcp-config.json` and the packages' plugins (`ownServers`). Plugin packages go as `--plugin-dir` (`docs/packages.md`).
- The monthly allowance and no prompt cache countdown: the transcript has what a session spent, not what is left, so a folder with a token has its month read from GitHub's API (BTN-341, "Limits of OpenCode and Copilot" below) and one on the machine's sign-in has no limit bars; its cache lives 1800 s, which `CacheTtl` (5 min or 1 h) cannot carry, so the page shows none, as for Codex and OpenCode.
- One transport only: the Agent SDK (BTN-239) is Claude's, so a Copilot folder, a token one too, has no transport (`transportOf` is `null`, its card says none), and the adapter has no `Agent.reply` and its entries do not steer. An answer or a limit resume is a new turn with `--resume` once the last one is over, as for Codex and OpenCode, and a chat message mid-turn waits for the mailbox or the turn's end.
- The checkpoint threshold, the chat mailbox and the standards come from the package's hooks in their top-level `additionalContext` shape; a chain session took the threshold's nudge and handed over, and took a standard's document on a read (2026-10-31, `verified.md`); its edits were not refused then, and since BTN-640 they are, checked by tests only (`unverified.md`). What Copilot does not get yet: a stall watchdog, `Agent.write`.
- No auto-compaction window setting (BTN-856, Copilot CLI 1.0.106): its compaction thresholds, `infiniteSessions.backgroundCompactionThreshold` (0.80) and `bufferExhaustionThreshold` (0.95), shares of the window, are session parameters of the SDK (JSON-RPC) only. In `-p` the CLI has no flag, no `copilot config` key and no environment variable for them; `COPILOT_PROVIDER_MAX_PROMPT_TOKENS` acts on a provider of one's own (BYOK) only, not on the subscription's models. So the Agent card has no window field for Copilot, and its window is the transcript's `maxPromptTokens`.

- Early CLI refusals (BTN-549): after a turn exits, `CopilotCli.error` reads the terminal plain-text `Error:` from its last output file. `withTurnError` supplements the tail, history and whole transcript even if `events.jsonl` is absent or holds only metadata. Registry sessions remain discoverable by transcript ownership without that file. A model refusal is an error, with a localized explanation and a button to the project's session settings; change Model or the task's model label, then choose New session. No model is substituted. A turn with no sign-in at all (BTN-624: a `none` folder on a machine with neither `gh` nor a token) prints a paragraph that ends with a list of the ways in, not an `Error:` line, so it is told by its first line, "Copilot can be authenticated with GitHub using …": an error `copilot.notSignedIn` with a button to the accounts — `gh auth login` as the user Even Keel runs as, or a Copilot account with its own token, then New session. The CLI writes `session.start` before it refuses, so the launch succeeds and the refusal shows on the session; exiting before that, it fails the launch with the same notice. The account card is not warned separately: such a folder still counts as signed in, and its card already says the machine's sign-in could not be read (`usage.copilotMachine`). A running turn, a successful result, later transcript activity or a replacement turn's output suppresses the old refusal. The live CLI check and page captures are logged in [verified.md](../verified.md).

## GitHub Copilot CLI (BTN-213, research)

The research behind the adapter above: what the Copilot CLI gives against the `Agent` contract and how it differs from OpenCode signed in with Copilot (BTN-215's description holds the full table, the comparison and what was not checked). Checked live on 2026-10-19 with Copilot CLI 1.0.98 on Windows (`winget install GitHub.Copilot`), a scratch `COPILOT_HOME`, model `auto`, two turns at 1 premium request each, from a terminal, not from the service.

- **A turn is a process**, as with Codex and OpenCode: `copilot -C <dir> -p "<prompt>" --output-format json` prints JSONL events and exits; the last line is `{"type":"result","sessionId":…,"exitCode":…,"usage":{"premiumRequests":…}}`. `--resume=<id>` (or `--session-id <uuid>`, which also sets the id of a new session) goes on in the same session and appends to the same transcript. Non-interactive runs need `--allow-all-tools` (or `--allow-all`/`--yolo`) for any tool; `--no-ask-user` drops the `ask_user` tool, so a question is the text the turn ends with; `--no-auto-update` pins the binary.
- **The transcript is JSONL**: `<COPILOT_HOME>/session-state/<uuid>/events.jsonl`, next to `workspace.yaml` (`id`, `cwd`, `name`, timestamps). Persisted events: `session.start`, `session.model_change`, `user.message`, `assistant.turn_start`, `assistant.message` (`model`, `content`, `toolRequests`), `assistant.turn_end`, `session.usage_record` per model call (`inputTokens`, `outputTokens`, `cacheReadTokens`, `cacheWriteTokens`, `reasoningTokens`, `cost` in premium requests), `session.shutdown` (`accountingSnapshot` with `totalNanoAiu` and `totalPremiumRequestCost` for the whole session). Deltas and MCP status are `ephemeral` and only on stdout. A model call reported a prompt cache lifetime of 1800 s.
- **Usage, not limits**: the transcript carries what a session spent (AI credits as `totalNanoAiu`, premium requests), not what is left of the plan; the remaining budget is only in the interactive footer and `/usage`. `--max-ai-credits` caps a session. The one exception, seen on 1.0.98 (2026-10-31): a refused model call prints `model.call_failure` to stdout (`ephemeral`, not in `events.jsonl`) with `quotaSnapshots` — per quota (`chat`, `completions`, `premium_interactions`) `entitlementRequests`, `usedRequests`, `remainingPercentage`, `overage` and `resetDate`. A successful call carries none, and the free plan's `chat` quota went down by ~0.1–0.3 for a one-word turn and ~1.1 for one reading ~15 files, so it is counted in tokens, not in prompts.
- **The account folder is `COPILOT_HOME`** (config, `session-state/`, `session-store.db`, `hooks/`, `mcp-config.json`, plugins, logs), but not the sign-in: the OAuth token sits in the OS keychain under `copilot-cli`, and `gh auth token` is the last fallback, so a fresh `COPILOT_HOME` ran under the sign-in already on the machine. One identity per session needs `COPILOT_GITHUB_TOKEN` (a fine-grained PAT with the "Copilot Requests" permission or an OAuth token; classic `ghp_` tokens are refused), which beats every stored sign-in.
- **Instructions and skills**: with a scratch `COPILOT_HOME`, `copilot instruction list` in this repository showed only its `CLAUDE.md`, and `copilot skill list` only the built-in skills: `~/.claude/CLAUDE.md` and `~/.claude/skills` were not picked up. `--no-custom-instructions` drops the repository's files too.
The three points below are from `--help` and GitHub's docs, not run.

- **Hooks take the Claude format**: PascalCase events (`PreToolUse`, `PostToolUse`, `Stop`, `SessionStart`, …) with snake_case payloads and Claude tool names in matchers, from `<COPILOT_HOME>/hooks/*.json`, `.github/hooks/*.json`, a plugin's `hooks.json` and the repository's `.claude/settings.json`/`settings.local.json`, the last only in a trusted folder; `--plugin-dir` loads a plugin in the Claude Code format. Seen live (1.0.98, 2026-10-27): the input is Claude's plus a `traceparent`, with `tool_result` for Claude's `tool_response`; tool names come as Claude's (`view` → `Read` with `tool_input.path`, `powershell` → `Bash`, `apply_patch` → `Edit` with the patch as a bare string, 2026-10-31). A committed `.claude/settings.json` hook ran in none of six chain sessions in a folder outside `trustedFolders`, while the same command from `<COPILOT_HOME>/hooks` ran on all four events; with the repository in the account folder's `config.json` `trustedFolders` it ran on all four too, in the worktree, MCP tools named `plugin_<plugin>_<server>-<tool>` (2026-10-31, [`verified.md`](../verified.md), "Copilot"). So since BTN-645 Even Keel trusts the repository itself: picking Copilot for a project is the consent, and before every turn, a resume too, `trustFolder` (`src/copilot/home.ts`) adds the main checkout to `trustedFolders` of the account folder's `config.json`, the other keys kept and a path already there under any spelling not added twice. The CLI writes that file with a `//` comment header ("User settings belong in settings.json. This file is managed automatically."), so it is read as JSONC and the header written back; a strict parse refused every such folder and paused the chain (TSK-52, 2026-11-01). A `config.json` that is not even JSONC fails the launch with `copilot.startFailed` instead of being overwritten. `--trust-folder` would need no file, but the checked 1.0.98 refuses it. `hookSpecificOutput.additionalContext` reaches the model on `PreToolUse` and is dropped on `PostToolUse`, a top-level `additionalContext` reaches it on both — so Even Keel starts Copilot with `EVEN_KEEL_AGENT=copilot` and the checkpoint package's hooks answer in the top-level shape there (BTN-467). From the docs only: `Stop` can block with a `reason` that becomes the next prompt.
- **MCP**: `--additional-mcp-config <json|@file>` adds servers for a run on top of `<COPILOT_HOME>/mcp-config.json` and the project's `.mcp.json`/`.github/mcp.json`; there is no strict mode, so the project's servers go off one by one with `--disable-mcp-server <name>`, and the built-in GitHub server with `--disable-builtin-mcps`. Seen live (1.0.98 and 1.0.105, 2026-10-31, [`verified.md`](../verified.md), "Copilot"): the flag keeps a project's server from starting while the `--additional-mcp-config` one starts, and a prompt-mode turn loads the project's `.mcp.json` only in a trusted folder (`trustedFolders` in `<COPILOT_HOME>/config.json`, or `--trust-folder` from 1.0.105). Even Keel trusts the project's checkout for its hooks (BTN-645, above), so the flag is what keeps the project's servers off.
- **Paths**: file access is limited to the working folder and the temp folder; a merge into the main checkout from a worktree needs `--add-dir <main checkout>` or `--allow-all-paths`.
