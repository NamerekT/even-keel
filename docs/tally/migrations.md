# Tally's migration steps

Every migration step of Tally's database, in order. Migration step N is the file `src/migrations/N-*.sql` (step 1 is `src/schema.sql`) and gives schema version N; how the steps run is in [`collector.md`](collector.md#schema-version-and-migrations-btn-133). What a table or view holds is in [`schema.md`](schema.md); an entry says only what its step changed. "State step N" is a step of Even Keel's own database (`docs/storage/steps.md`).

1. `schema.sql`, the schema of the first release.
2. `2-false-rule-deletions.sql` (BTN-150) removes the deletions of runs that lost every live project rule file at once, with their snapshot changes.
3. `3-gpt-family.sql` (BTN-170): `task_estimates` knows the `gpt` model family.
4. `4-compactions.sql` (BTN-254): the view `compactions`.
5. `5-milestones.sql` (BTN-172): `tasks.milestone`, asked again of every fetched task, and the view `milestone_costs`.
6. `6-task-sources.sql` (BTN-66): `tasks.profile_id` and `tasks.url`.
7. `7-task-followups.sql` (BTN-362): `tasks.created_at`, asked again of every fetched task, and the view `task_followups`.
8. `8-handoff-headings.sql` (BTN-87): the headings of `handoff_notes` skip fenced code blocks.
9. `9-codex-stray-counts.sql` (BTN-626) deletes the `codex:` rows of a Codex session from its first record row on, responses counted twice; a re-read is idempotent by key and would not remove them.
10. `10-rework-label.sql` (BTN-785): `audit_tasks`, `task_repeats` and `task_followups` take the built-in tracker's `Rework` beside `Переделка`.
11. `11-catalogue-prices.sql` (BTN-859): `messages.provider` (Anthropic for older Claude rows, OpenAI for Codex's), the read marks of OpenCode's databases forgotten so they are read again and their responses get one, `model_prices.source` with the key `(source, model)`, and `message_costs` with a catalogue price and `price_source` ([`cost.md`](cost.md#the-price)).
12. `12-key-spends.sql` (BTN-860): the table `key_spends` and the view `message_paid` ([`cost.md`](cost.md#real-spend-on-a-key-btn-860)).
13. `13-normal-spans.sql` (BTN-966): `audit_sessions`, `audit_tasks` and `task_repeats`, with the same columns, leave out of stuck spend and span counts the spans whose current reason is `normal` (a span without a reason, or `other`, counts); `stuck_spans` keeps every span. The `/stats` overview and the before/after reader use the same filter (test: the root's `src/stats/stuck-reader.test.ts`).
14. `14-model-families.sql` (BTN-967): `task_estimates` takes its family from the same expression as `/stats` (`familyOf`, the root's `src/stats/base-sql.ts`): Claude families with Fable, GPT tiers (`sol`, `luna`, `astra`, `terra`) or a bare `gpt`, DeepSeek, Qwen, Gemini, Kimi, GLM, Mistral and Llama; an unknown model gives null (test `src/model-families.test.ts`).
15. `15-task-moves.sql` (BTN-1076): the table `task_moves (old_task, task)`; `session_tasks` gives a session of an old id the new one ([`cost.md`](cost.md#a-project-moved-to-another-tracker-btn-1076-srctask-movests)). Raw rows (`sessions.launch_task`, `messages.task`) keep the old id (test `src/task-moves.test.ts`).
16. `16-minimax-family.sql` (BTN-1204): `task_estimates` again with `familyOf`'s expression, which adds MiniMax (`minimax/minimax-m3.1-flash` → `minimax`).
17. `17-machines.sql` (BTN-1280): `messages.machine` and `sessions.machine` ([`collector.md`](collector.md#machines-elsewhere-btn-1280)). No view changes: the views name their columns, and `/stats` reaches the machine through `sessions`.
18. `18-chat-sessions.sql` (BTN-1233): the table `chat_sessions`; `session_tasks` and `message_costs` give a chat's session no task (tests `src/chat-sessions.test.ts`, the root's `src/stats/chats-reader.test.ts`).
19. `19-limit-shares-one-pass.sql` (BTN-1351): `limit_shares` with the same columns and rows, computed in one pass ([`cost.md`](cost.md#limit-share)). The first body joined every response with every interval of its account and filtered by time after the join: 122 million rows and 17–29 s a read on the live database, past the stats reader's statement timeout (test `src/limit-shares.test.ts`, against the first body).
20. `20-warm-pings.sql` (BTN-1413): the table `warm_pings` and the view `warm_ping_costs`; `limit_shares` and `task_costs` take the pings in (test `src/warm-pings.test.ts`).
21. `21-session-activity.sql` (BTN-1470): the table `session_activity` and `compaction_nodes` with its insert trigger, which the `compactions` view now uses. The first collector on this schema projects the history in cursor batches under the `tally_meta.session_activity` mark. Drops the unused index `sessions_machine`. On a copy of the working database neither a pass nor `/stats` read a block of `lines` after it ([the check](../verified/page.md)).
22. `22-line-raws.sql` (BTN-1471): the raw row moves out of `lines` into `line_raws` ([`schema.md`](schema.md)). Nothing is copied in batches: the old table is renamed `line_raws` whole (heap, TOAST, key, grants) and loses its narrow columns by `drop column`, which rewrites nothing, and a new `lines` gets a copy of those columns, about 100 bytes a row. The dropped values stay as dead bytes in the heap of `line_raws` until something rewrites it; no `VACUUM FULL` is needed. The `compaction_nodes` trigger moves to inserts into `line_raws`.
23. `23-worktree-visits.sql` (BTN-1615): `session_tasks` and `message_costs` give a session without a launch a worktree folder's task only when it started there or spent most of its responses there ([`schema.md`](schema.md#a-responses-task)). Before it, BTN-1546 got 4 h of active time and $55.6 of a session that only cleaned up worktrees, against $0.48 of its own. The views recompute the history; a time report already written is not ([`time.md`](time.md#time-reports)).
24. `24-limit-shares-stored.sql` (BTN-1658): the materialized view `limit_shares_stored` ([`cost.md`](cost.md#limit-share)).
