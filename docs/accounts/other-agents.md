# The folders of other agents

Codex, OpenCode and Copilot. What they share with Claude's folders — the global folder hidden until registered, adding, removal, the name across sign-ins — is in [`folders.md`](folders.md); keys of any agent in [`claude-kinds.md`](claude-kinds.md), "Keys of any agent". A folder name is its account key across all four roots: a new one is named apart from every other agent's folder (`folderName`).

## The Codex folders (BTN-168, BTN-176)

- **The folders.** Codex's own folder `CODEX_HOME` or `~/.codex`, key `codex`, listed once it exists and is registered (Codex does not create it); and one `CODEX_HOME` per added account under `~/.codex-accounts/<name>` (`EVEN_KEEL_CODEX_ACCOUNTS_DIR`; `AccountHomes`, `src/account/homes.ts`). `CODEX_HOME` isolates everything — `auth.json`, `sessions/`, `state_5.sqlite`, `config.toml` — so each folder has its own sign-in, limits and sessions. A Codex folder named like a Claude one by hand is not listed.
- **Adding and removal** go as Claude's: "+ Add" (`account/add` with `agent: "codex"`) signs in in a `.pending-*` folder with `codex login --device-auth` and names it by the e-mail; removing an added folder runs `codex logout`. The device code is shown as the page's [device sign-in](page.md#adding-btn-352). Unlike Claude's, no Codex account is given to an app (`account.codexApp`).
- **The sign-in status** is `codex login status`: "Logged in using ChatGPT", an API key (below) or "Not logged in"; the e-mail and plan come from the `id_token` claims. "Renew" runs `codex login --device-auth` again; sign-out is `codex logout`.
- **The folder's configuration.** A new folder has no `config.toml`: its model is the shared or the project's `models.codex`, else Codex's default. `~/.codex/config.toml` is not copied, so a model set there — one the free plan refuses, such as `gpt-5.4-mini`, among them — does not reach the new folder. Nothing else is transferred either: the project's plugins and MCP servers come with every turn as packages (`docs/packages.md`), so a new folder needs nothing installed.
- **The account a session runs on.** A Codex account takes the Even Keel role like a Claude one ([`folders.md`](folders.md), "Active account"). A Codex session starts in the pool's `accounts.codex` (`codex` by default; `docs/sessions/models.md`, "Run profiles"), and the chain judges a Codex task's launch block, limits and handoff account by that folder, not by the active one.
- **A spent limit.** The chain waits for the reset, or goes on at once by a handoff when the task's pool entry is moved to another ready account (`relayStep`, `src/chain/relay.ts`) — as with Claude. Even Keel moves no pool entry by itself; the switch "Go on where a limit is left" moves only a task never launched, to another machine (`docs/machines/pool.md`, "Past a limit").
- **Limits** of a ChatGPT sign-in are polled from ChatGPT, the folder's rollouts being the fallback (`docs/sessions/limits.md`, "ChatGPT (Codex and OpenCode)"); Tally collects the rollouts of every Codex folder (`docs/tally.md`).

### One free ChatGPT account across Codex and OpenCode (BTN-987)

- **The rule.** One free ChatGPT identity per installation, with at most one folder of it in each agent. Paid and unknown plans do not count.
- **What the person sees.**
  - Adding a different free identity is refused (`account.secondFree`): the new folder is signed out and removed. The sign-in window (`planRefused` in `web/src/accountAdd.ts`) folds the CLI's earlier success under "CLI output: the sign-in, before the plan check" and offers "Sign in with another account".
  - The same e-mail (case insensitive) may have one folder in each agent; a second folder in the same agent is refused (`account.sameFree`).
  - Extra free folders already there show `account.extraFree` and can neither start sessions nor take the Even Keel role; the first identity's folder in each agent stays usable.
- **How it is counted** (`extraFree`, `secondFreeProblem` in `src/account/model.ts`, in the folder order). Codex reads `chatgpt_plan_type` from its `id_token`, OpenCode from its OpenAI OAuth access token (`AccountStatus.chatgptPlan`, "The OpenCode folders" below); only the explicit plan `free` counts. Without an e-mail the shared identity cannot be confirmed. Every status refresh, a restart included, counts it anew from the folders; nothing is stored, so no folder stays allowed by an earlier count.
- What was not checked live: [unverified](../unverified/accounts.md#one-free-chatgpt-account-across-agents-btn-987).

### On an OpenAI API key (BTN-177)

- **What is written.** "API key" in the Codex step of adding (`account/api` with `agent: "codex"`) makes a folder under the Codex root, named as Claude's API folders are, with `auth.json` = `{ "auth_mode": "apikey", "OPENAI_API_KEY": "…" }` — what `codex login --with-api-key` writes. Codex reads the key from there on every turn, so the turn's environment is unchanged. `codex login status` words it "Logged in using an API key" or "API key configured" by version (BTN-383); both read as a key (`parseLoginStatus`, `isApiKey`). The key is in the folder in plain text, as Claude's is in `settings.json`.
- **The check.** Before the folder is made, `GET https://api.openai.com/v1/models` (`checkOpenAiKey`, no tokens): 401 or 403 refuses it (`account.codexKeyRejected`), anything else refuses it as unchecked (`account.codexKeyUnchecked`); then hourly, as Claude's. The free-account rule does not apply: a key is used under OpenAI's API terms, not ChatGPT's.
- **Spend.** Today's spend comes from Tally as for Claude's keys (Codex rollouts are priced by GPT model, `docs/tally.md`); a model Tally has no price for shows no figure.
- **Out of credit** (BTN-195). OpenAI answers 429 `insufficient_quota`; the rollout fold takes Codex's "Quota exceeded. Check your plan and billing details." or OpenAI's own "You exceeded your current quota" as `credit` (`CREDIT_TEXT`, `src/codex/rollout.ts`), while any other `quota`, `usage limit` or `rate limit` stays `limit`. The texts seen live: [verified](../verified/accounts.md). The wait and the check: [`claude-kinds.md`](claude-kinds.md), "A key out of credit".

## The OpenCode folders (BTN-214)

- **The folders.** Only added ones, under `~/.opencode-accounts/<name>` (`EVEN_KEEL_OPENCODE_ACCOUNTS_DIR`): OpenCode keeps its files in the user's XDG folders, shared with every OpenCode the user runs, so there is no "own folder" to list. A folder holds the four XDG folders (`data`, `config`, `state`, `cache`) and the empty `config/opencode/AGENTS.md` that keeps `~/.claude/CLAUDE.md` out (`docs/sessions/opencode.md`, "OpenCode").
- **Ways in** (`SIGN_INS` in `src/agent/providers.ts`, `LOGIN_METHODS` in `src/opencode/cli.ts`), chosen in the add dialog and sent as `account/add` with `agent: "opencode"` and `method`:
  - `chatgpt` — `opencode providers login -p openai -m "ChatGPT Pro/Plus (headless)"`, a device link and code, shown as Codex's;
  - `none` — no sign-in: the folder is made at once and runs OpenCode's own free models (`opencode/big-pickle`);
  - **OpenCode Go** — a Console key, checked with the Go usage endpoint before the folder is made (`account/api`, `agent: "opencode"`, `provider: "opencode-go"`), then saved as an API credential under `opencode-go`. Its prefix does not choose the provider: older Go keys share OpenAI's `sk-` prefix. A 403 accepts a Console key without Go; a 401 rejects it with instructions to create a new Console key. "Replace key" checks with Console and keeps the stored provider (`opencode-go` or the older `opencode`), folder, name and roles. Such a folder is a subscription for usage polling, not a per-token API account; the key stays out of the page state and of the OpenAI key and credit checks;
  - an API key (`account/api` with `agent: "opencode"`) — written into `data/opencode/auth.json` as `opencode providers login` writes it, `{ "<provider>": { "type": "api", "key" } }`, under `anthropic` for an `sk-ant-` key, `openrouter` for an `sk-or-` key and `openai` for any other (`keyVendor`), and checked with that provider's API as Claude's and Codex's keys are (`keyProvider` in `src/account/homes.ts`).
- **No Claude subscription.** Anthropic allows the Pro/Max sign-in only in Claude Code, and OpenCode dropped it: Claude runs in OpenCode only on an API key. The add dialog says so under the API key way.
- **Copilot is visible but unavailable (BTN-573).** OpenCode on Copilot is blocked until a live check enables it (`docs/sessions/opencode.md`, "OpenCode on Copilot is blocked"). Adding or renewing that sign-in is unavailable; existing credentials and their credits stay visible with an unsupported note. A folder holding only Copilot cannot be picked or switched to and is not ready in setup or the project wizard; a mixed folder stays usable with its other providers. Model suggestions omit Copilot, and the server's launch, resume and write refuse it too.
- **The status** comes from `auth.json`, not a CLI call: no file is a folder on `none`; `subscriptionType` keeps the provider list. For OpenAI OAuth, `parseAuth` reads `https://api.openai.com/auth.chatgpt_plan_type` into `chatgptPlan` and `https://api.openai.com/profile.email` into `email` from the saved access token, with no network request or renewal; missing or malformed claims stay unknown. The CLI owns renewal, so a plan change shows once its saved token changes. Sign-out deletes `auth.json`.
- **The name.** A new ChatGPT folder is named by its e-mail; with none known, or with no sign-in, after the agent (`opencode`, `opencode-2`…). Existing folder keys stay.
- **Several providers.** One folder may hold several; the run profile's model (`<provider>/<model>`) picks the one a session uses.
- **Limits** of ChatGPT, Copilot and Go — ChatGPT's 5-hour and weekly windows, Copilot's monthly allowance, Go's 5-hour, weekly and monthly windows — are read every five minutes from the provider's API (`docs/sessions/limits.md`, "Other agents' limits"). A folder on ChatGPT and a Codex folder on the same ChatGPT account share one limit, and both cards say so. Free models and other API keys have no known windows. A Console key without Go stays Zen; an expired Go key asks for "Replace key".
- **An account whose limit nothing tells** (OpenCode Zen, Copilot on the machine's sign-in; BTN-342) shows what is known instead: its tokens from Tally, cache included, since local midnight and over the last 30 days (`/api/stats/tokens`, `docs/stats.md`; how the row shows them: [`page.md`](page.md), "The page `/accounts`"), and "last refused by its limit …" once a chain session hit it (`AccountEntry.lastLimitAt`, from `LimitRetries`, in memory since the start). Tokens, not dollars: Tally prices neither the free models nor Copilot's. On such a limit the chain tries again with a growing wait (`docs/chain/exceptions.md`, exception 1). The free models' limits have no numbers anywhere: OpenCode publishes none and the list of free models changes.

### OpenRouter (BTN-843)

An OpenCode folder on an `sk-or-` key. With it `opencode models` lists OpenRouter's whole catalogue, so a task's run names a model as any other OpenCode one: `openrouter/minimax/minimax-m3.1-flash`.

- **The key check.** `GET openrouter.ai/api/v1/key` (`checkOpenRouterKey`): 401/403 refuse it (`account.openRouterKeyRejected`), anything else refuses it as unchecked (`account.openRouterKeyUnchecked`). An answer with `is_management_key: true` is refused too, on adding and in "Replace key" (`account.openRouterManagementKey`): a management key takes no model request (BTN-1205).
- **Out of credit.** A session's 402 ("Insufficient credits", "requires more credits") is a stop on credit (`CREDIT_TEXT` in `src/opencode/transcript.ts`). The money is checked by one output token of the cheapest paid text model of `/api/v1/models` (`checkOpenRouterCredit`; a 402 is still empty) — a free model answers with no money, so it would tell nothing.
- **The key's own limit** (BTN-847). The same `/api/v1/key` answer has `limit`, `limit_remaining` and `limit_reset` (`openRouterLimit`), read at each check of the key and with each read of its spend (`readOpenRouterKey`, BTN-860), kept in memory by `KeyChecks` (`noteLimit`) and given to the page as `AccountEntry.keyLimit`. A key with no limit gives nothing.
- **The balance** — `total_credits − total_usage` of `GET /api/v1/credits` — is read on saving a management key, with the hourly key check and with each read of the spend, kept in memory and given as `AccountEntry.balance`; a failed read keeps the last one.
  - It is read with the account's own key first (BTN-1206): OpenRouter documents `/credits` for a management key only, yet it answers a session's key with the same totals ([verified](../verified/opencode.md)).
  - Once it refuses the own key (401/403), the watcher remembers that (`ownKeyRefused`, in memory, until the folder's key changes) and asks the management key instead; with none, the balance leaves the card.
- **The management key** (BTN-868) is the optional way when the own key is refused: "Management key" in the row's ⋯ menu, only on an account on an OpenRouter key (`AccountEntry.managementKey`, `false` without one), opens `ManagementKeyDialog` (command `account/management-key`, `AccountWatcher.setManagementKey`).
  - Before it is kept it reads `GET /api/v1/credits` (`readOpenRouterBalance` in `src/account/management.ts`): 401/403 refuse it (`account.managementKeyRejected`), an unreadable answer keeps nothing (`account.managementKeyUnchecked`); an empty value removes the key.
  - It is kept in the state database (`management_keys`, `docs/storage.md`), never in the account folder its sessions read, and the page gets only the boolean. OpenRouter refusing it later gives the balance `{ rejected: true }`.
  - Removing the management key keeps a balance the own key reads; removing the account removes its key.
- How the page shows the key limit and the balance: [`page.md`](page.md), "The page `/accounts`".

## The Copilot folders (BTN-215)

- **The folders.** Only added ones, under `~/.copilot-accounts/<name>` (`EVEN_KEEL_COPILOT_ACCOUNTS_DIR`), each a `COPILOT_HOME` (`src/copilot/home.ts`): config, `mcp-config.json`, `session-state/`. `~/.copilot` is not listed: it is the user's own Copilot, as `~/.local/share/opencode` is OpenCode's. Before a turn Even Keel adds each project's checkout to `trustedFolders` of the folder's `config.json`, so the repository's hooks run (BTN-645, `docs/sessions/copilot.md`).
- **Two ways in** (`SIGN_INS`):
  - `none` — "This machine's sign-in": the folder is made at once (named `copilot`, `copilot-2`…) and its sessions run on the CLI's sign-in available in that folder (below);
  - a token (`account/api` with `agent: "copilot"`) — a fine-grained PAT with the "Copilot Requests" permission (`github_pat_`) or an OAuth token (`gho_`, `ghu_`); a classic `ghp_` token is refused (`account.copilotTokenInvalid`), as Copilot refuses it too. It is kept in the folder's `even-keel.json` and handed to every turn as `COPILOT_GITHUB_TOKEN`, which beats the stored sign-in, so each such folder is its own GitHub identity. It counts as a key: checked with `GET https://api.github.com/user` before the folder is made and hourly after (`checkGitHubToken`; 401 or 403 is `account.copilotTokenRejected`, anything else `account.copilotTokenUnchecked`); a refused one makes the account `needsLogin`. Default folder name `github`.

### The machine's sign-in

- **Where the CLI keeps it.** `copilot login` keeps its token in the OS credential store under `copilot-cli`, with a plaintext fallback in `config.json` when the store is unavailable ([GitHub's authentication reference](https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/authenticate-copilot-cli)); the CLI can also fall back to `gh auth token`.
- **Its status.** `CopilotCli.authStatus` asks `machineSignedIn`: the same binary, `COPILOT_HOME` and environment as sessions, `auth.getStatus` over `--headless --stdio` (`src/copilot/machine.ts`). An explicit `isAuthenticated: false` marks it signed out, true signed in. An unavailable CLI, a timeout or an unreadable, empty or missing status gives `AccountStatus.loggedIn: null`: the card says "Could not check" and launches stay allowed (EKR-84). Every refresh, a restart included, asks again and replaces the verdict. A folder's own Even Keel token keeps its priority and key checks.
- **The token for the allowance** (`machineToken`). Only an authenticated `gh-cli` answer for GitHub.com permits `gh auth token --hostname github.com --user <the CLI's login>`; an own OAuth sign-in, another host or an unreadable answer gives no allowance, and no other account is put in its place. The token exists only during the allowance request, never in logs, state or a cache.
- **Signing in from a terminal.** A signed-out folder gets `Agent.terminalLogin` (`AccountEntry.terminalLogin`): the problem band shows a command to copy instead of a web sign-in button. Run it on the service's machine as the service's user: in cmd on Windows, standard sh on Linux and macOS. It removes `COPILOT_GITHUB_TOKEN`, `GH_TOKEN` and `GITHUB_TOKEN` in a child cmd or sh, sets the folder's `COPILOT_HOME` and runs the sessions' binary, so the terminal's own environment is left as it was. There is no web terminal, recheck button or copying from `~/.copilot`.
- **Linux without a keyring** (EKR-48). The CLI asks there whether to keep the token in plain text in `config.json`, and a piped web sign-in cannot answer: sign in in an interactive terminal with the folder's `COPILOT_HOME` — the command above does it — and the token lands in that folder. Without the variable it lands in `~/.copilot` instead, and without a terminal it is not saved at all ([verified](../verified/copilot.md); [the guide's workaround](../guide/setup.md)).
- What was checked and what is left: [verified](../verified/copilot.md), [unverified](../unverified/copilot.md#copilot-folder-sign-in-refresh-ekr-73).

### The monthly allowance (BTN-341, BTN-520)

- Copilot's budget is AI credits or premium requests, which the CLI tells only in its interactive footer.
- **A token folder** has its month read from GitHub — `copilot_internal/user`, else the billing API, which needs the token's "Plan" read permission (the card names it when missing) — and shown as one bar, "N left, resets on the 1st", or the requests used when only the billing API answers. The drawer's narrow column shows what is left as the bare number, its hint "N left". The sources in detail: `docs/sessions/limits.md`, "Other agents' limits"; the overage permission and the month's net spend: [`page.md`](page.md), "Subscription credits and extra usage".
- **The machine's sign-in** reads `copilot_internal/user` only when the CLI confirms its GitHub CLI fallback, directly, without an editor-identification header or a model-token exchange; otherwise it has no allowance. Checked on Windows under the service; Linux keyring access, macOS OAuth and other sources are [unverified](../unverified/copilot.md#copilots-machine-token-and-model-availability-btn-516).
- **A token folder counts as a key but is polled like a subscription** (`Agent.keyUsage`): a spent budget or a limit waits for the month's reset, not for a credit check. No Tally figure on the card: Tally prices a Copilot call at the model's API price, not at its credits.

### One free account

GitHub's terms allow one free account per person, and Copilot Free comes with it. Even Keel cannot see a token's plan, so unlike Codex it does not check: several tokens are for several paid seats or several people's own accounts, not to get round one free budget.
