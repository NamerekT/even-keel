# Accounts on the page

The drawer, the page, adding and switching, credits, a machine's accounts, the desktop app.

## Accounts: the drawer, the page, adding, switching (BTN-169)

The server side is the same `account/*` commands for all four; the shared parts are in `web/src/layout/accountParts.tsx`.

The row menu's left edge follows the click's viewport X coordinate, clamped inside the window. It opens below the row, or above when space is short. Enter/Space uses the existing anchor at one third of the row button's width; a keyboard opening clears any earlier click coordinate. Both the row's background and its overlay button use the same toggle handler; independent tips and controls keep their own actions.

- **The account's name** (`accountName`, `web/src/accountName.ts`) is shared by the header, drawer, page, settings and statistics: the given name, else e-mail, else provider, numbered when names coincide. The folder key stays its identity and appears in the mark's tip. Rename is in the row menu (`AccountRowMenu`): Apply saves through `account/name`, Cancel or Escape abandons the edit, and an empty name restores the default. Only the saved display name changes, never the folder.

- **The account mark** (`AccountMark`, `accountParts.tsx`) is a coloured dot and muted agent icon before the name. Its tip (`Tipped`) holds the agent, connection, sign-in left, folder and pending configuration. Colour follows `entrySlot` in `web/src/accounts.ts`. Shared subscription limits have a separate ⇄ mark with `sharedLimitText` in its tip; source and freshness are in the percentages' tips (`staleText`, `limitsNote`).
- **The row menu** (`AccountRowMenu`, `rolesOf` in `AccountRoles.tsx`) opens by clicking the row or pressing Enter/Space on its button. It offers the real roles: Even Keel on every agent and VS Code on Claude; the Claude desktop app is not switchable. Held roles have a check; unavailable roles and Remove show their reason and stay keyboard reachable. Arrow keys move, Escape closes and returns focus. At 760 px and below the menu's head, before the roles, is the row's counters (`MenuMeters`, BTN-1043): the plan's windows and the models' weeks (BTN-805) by their full names with the used percentage and the reset, then one muted line with the reading's source and age and the outdated or stale notes. It is no item and takes no focus; accounts that show sums instead of windows have none, and a wide row, which shows the counters itself, never repeats them there. Rename opens a modal, Remove uses `removeProblem` and `ConfirmDialog`. Sessions, transport and shared-limit tips act independently. Role chips name Even Keel in accent, apps in green, and Not used with a dashed outline; unused names are muted.
- **Working now** (`AccountWork`, same file) — the account's live sessions under the roles: chain and Even Keel sessions by their CLI name, VS Code chats by their tab title with "VS Code · working/open". The title is the last `custom-title` in the transcript, else the last `ai-title` (`titleOf`, `ChatTitles` in `src/sessions/title.ts`, which reads the transcript's last 256 KB and caches it by size); without either, the CLI name.
- **The drawer** (`AccountPanel`, `web/src/layout/Account.tsx`; BTN-1669 brought back v0.3's after BTN-1587 had put the page there) is narrow, 640 px for the nested groups, the whole width on a phone. Under its title and × one row of two buttons of one size: "+ Add account" at the left (it closes the drawer and opens the add dialog) and "All accounts →" at the right, to `/accounts` (closing the drawer; in a machine elsewhere's view to `/accounts?machine=<id>`). Then the summary of the accounts with problems (`AccountProblems`, see the page below), the yellow band of `settings.json` changes made right in a folder (`AccountSettingsEdits`, see "Transferring the shared configuration"), then the page's agent cards and connection groups in the page's order, a mini version of it (`AccountGroups` without `page`, `accountRows.tsx`, `accountRows.css`), with two columns: the account with its role under the name, and the limits or the two sums; window names are short there ("5 h", "wk", "mo"). A press on the header's account block opens it in every view: the hub's accounts on the hub, in "All machines" and in the own machine's view, a machine elsewhere's in its view (see [machines](../machines.md)). The chain's account comes first, other accounts at work before idle ones. The burger has one Accounts button with the active account's tightest used percentage and a red dot for account errors; it opens the drawer of the view (`ViewAccountPanel`). Pointing at the block still shows the read-only levels, with no link to the page.
- **The sign-in dialog** (`LoginDialog`, `web/src/layout/LoginDialog.tsx`) — a renewal or sign-in started from the drawer or a card opens a modal with its steps (`LoginSteps`: the link — for Claude "On this computer", the primary one, and "From another device" — the code field, the CLI output), unless the add dialog is open, which shows the same steps itself. It follows the server's `account.login`, not the click, so it is there in every tab and after a reload and goes once the sign-in ends. × and Escape cancel the sign-in (`account/cancel`): left running out of sight, it would keep every sign-in button greyed with nothing on screen, which is how the steps at the drawer's bottom read before. A backdrop click does nothing, so a stray click on return from the sign-in tab does not end it.
- **The page `/accounts`** (`web/src/pages/Accounts.tsx`) is a page of its own, the whole width, reached by the drawer's "All accounts →"; it holds the full table, with "+ Add account" in its head, and uses the same problems summary, agent cards and row menu as the drawer (BTN-576). A card per agent — Claude Code, Codex, OpenCode, GitHub Copilot — with its icon in a 28 px frame, the count and Add; the page also has Add account for a provider with no accounts. Empty agents are omitted. Inside a card, a group per connection (`accessOf`, `accessGroups` in `web/src/accounts.ts`): Claude subscription, Anthropic key, ChatGPT, OpenAI key, OpenRouter key (BTN-843, `--owner-openrouter`), OpenCode Zen, GitHub (GitHub Copilot inside OpenCode). An OpenCode folder goes by the provider whose limits it shows (ChatGPT, then Copilot), a key folder by the key's provider, one with neither is Zen. The plan (pro, max, plus, free) does not split a group and stays a tag after the name. A group's 3 px stripe is the colour of who bills it (`ACCESS_OWNER`, the `--owner-*` tokens). Each group has its own head: its name, count (a pill tinted by the text, since the group's grey fill would swallow the shared `.count-badge`) and column names. A subscription group's head says only Limits and each window is named in its row (variant 2 of BTN-575), so Plus with five hours and a week, Pro with a week only (`limitSpans` drops a window the provider's own answer left out) and Free with a month sit in one group; a key group has Today and 30 days in dollars (`/api/stats/spend`), a group whose accounts have no limit to read Today and 30 days in tokens. Rows share a page-wide grid: account and plan, Used by, limits, Extra usage, Sessions, Runs through. Problems (BTN-1420, `web/src/layout/accountProblems.tsx`): each account's go into one band under its row (`AccountProblem`), its notes and fixes without a path — red when it is an error (a sign-in needed, a refused or expired key or token, a failed check, the wrong account in the folder), yellow when it is a warning (a sign-in a day before the early end of its window, above; a token's last 30 days, a spending cap, removal pending, a second free account held; `problemTone`). Above the cards one band, red if any of them is an error, else yellow, only names the accounts: "Account X has problems" or "Accounts with problems: A, B" — with the agent (`Codex › Work`) where an account of another agent has the same name. Each name leads to its row, whose `id` is `account-<key>`: on the page through the address's anchor, so a copied link or a reload opens on the account; in the drawer by scrolling only. The row then glows once in its band's colour and the focus goes to its fix (`goToAccount`). An OpenCode folder on Copilot sits in its GitHub Copilot group with the role "Not supported yet" instead of "Not used" (BTN-573). At 760 px and below both page and drawer show dot, name, any spending chip, role and tightest used percentage (amber from 80%, red at 100%); windows, extra-usage values, sessions and transport are hidden, and the name/chip group can wrap. The percentage is of the plan's windows only: a model's own week never enters it, since a spent Fable week does not stop sessions on other models; an account with such a week gets a small tag with the model's name before the percentage instead (BTN-1043). The percentage has no tip there, so a tap opens only the row menu, whose head holds what the tip said. Newly added rows glow through `useFreshAccounts`. The Claude Code card alone also has the Even Keel marketplace action before Add (`AccountMarketplace`, EKR-62): a small registration button while unknown, a quiet check mark when registered. Its tip explains manual sessions and provides copyable registration and plugin-install commands. It is independent of account sign-in, disabled during the command, and absent with no marketplace data. Errors use the page's error notice, with an installation instruction when the Claude executable is missing. Server state determines registration after reload; no local dismissal is stored. Header actions wrap on narrow screens.
- **Adding** (BTN-352) — a modal over the current page (`AddAccountDialog`, `web/src/layout/AddAccountDialog.tsx`, rendered by `App`; the pure part in `web/src/accountAdd.ts`), not a page of its own: the setup and the project wizard stay where they are and their agent's readiness turns "signed in" after it. Its state is in the URL, `?addAccount=<provider>&addWay=<id>` (`addOf`, `withAdd`, `withoutAdd`; `?addAccount=` alone is the provider step), so a reload or a link reopens it. The names are its own because it opens over any page (BTN-629): `add` is the plugin dialog over a project's packages (`docs/packages.md`), which drops an `add` that is no plugin and so closed this dialog there, and `account` is the `/stats` filter and the `dev:fake` fixture; the old `/accounts/add?provider=…` redirects to `/accounts` with the dialog open (`legacyAdd`). An opener pushes a history entry and the provider pick another, each counting its depth in the entry's state (`addDepth`), so the browser's Back from the ways goes to the providers and closing goes back as many entries as were pushed, then drops `addAccount` from the one it lands on.
  - The provider step only when none is given: four compact cards; one whose CLI is not found is off with where to get it (`CLI_MISSING`). A provider whose checked copy is not ready, or whose installed CLI is missing, opens `CliDownloadDialog` over the provider pick (BTN-599): closing it leaves the pick open (Back to it, or the pick in place of an opener's provider), and a finished download goes on to the provider's ways. Where the installed CLI is missing and the service could install it (`EvenKeelState.account.installs`, BTN-1502), the dialog, the banner's `CliActions` and the setup's `CliSourceChoice` show the command with "Install" as the first button (`account/installCli`); its output follows under it (`InstallOutput` in `web/src/layout/CliInstall.tsx`) and the CLI is looked for anew at its end ([machines](../machines.md), "Installing a CLI from the page").
  - The ways in (`WAYS`): cards to pick (radio, icon, title, one line of what it gives, a check on the picked one), the long text in a "?" tip, and one primary button that names the action. Claude: Subscription, API key; Codex: ChatGPT subscription with the one-free-account rule under it, API key; OpenCode: ChatGPT, Free models (added at once, `NO_SIGN_IN`), API key, with the line that Claude through OpenCode needs a key; Copilot: This machine's sign-in (added at once), Token. A sign-in is `account/add` with the agent and, for OpenCode, the `method`; a key or a token is `account/api` with the agent, the key and the optional name. Claude's Subscription opens a second row of the same cards (`SignFields`, `SIGNS`): "Full sign-in" with what it gives under pluses and one honest minus, "Long token" with only what it lacks; the token card brings the reset warning, the `claude setup-token` command, the token field and "The same account as" ("Long-token accounts" above).
  - What is typed (`Drafts`: the way, the key, the name, per provider) lives in the dialog's state, so Back and forward keep it; the key is never written to the URL or storage. Closing with something typed asks "Discard?" (`dirty`).
  - A running sign-in: the dialog shows its steps (`LoginSteps`: numbered rows "Open the sign-in page", "Sign in", the code — a field, or the device code with "Copy" — the current row lit by `loginRow`, the CLI output folded under them). The rows follow what the person did in this tab, as the sign-in itself is on another site: the first until the CLI gives the link, the second once the link is clicked (any button), the third once the field holds text, the device code is copied or the service took the code. A focus is no step: the dialog opens before the link and focuses the code field meanwhile, then moves the focus to the link once it comes (BTN-529). A backdrop click and Escape do not close it; Back and × ask, then cancel (`account/cancel`). A sign-in already running when the dialog opens shows its steps. A failed one shows its error with "Try again" (`retryBody`) and "Close".
  - Success — the login turns `null` with no error and no cancel from the dialog, or a key or an instant folder is added: the dialog closes and the new card on `/accounts` glows.
  - The focus stays inside (`<dialog>`), Enter on a picked way presses the primary button; under 760 px the dialog takes the whole screen.

  A Codex or OpenCode sign-in (`deviceLogin`, by the login's `agent`) has no code field: the one-time code, which goes on the provider's page, is shown apart from the output, large and with a "Copy" button (`DeviceCode` in `web/src/layout/accountParts.tsx`); the button falls back to `execCommand('copy')` where the page has no clipboard API.
- Every place that shows a session — the current chain row, the session panel and its list of the task's sessions, the session and transcript windows, the last session on `/tools`, the session timeline of a task on `/stats` — names its account with a pill in the account's colour (`AccountTag`; the colour is the folder's place among the keys sorted, `accountSlot` in `web/src/accounts.ts`). The pill finds the account by the folder key or the e-mail the session holds (`accountOf`) and shows its `accountName`, the key and e-mail in the tip; an account no longer listed shows the e-mail's name part. A live session's account is its folder; a finished one's is the folder holding its transcript (`TranscriptOwners`, `src/sessions/owners.ts`, rescanned at most every 5 min on a miss), with the e-mail the folder had at the session's start.
- Limit bars turn amber from 80% and red at 100%, in the panel and in the header.
- For now there is one app — VS Code: its account is `CLAUDE_CONFIG_DIR` in `claudeCode.environmentVariables` of the user `settings.json` (`%APPDATA%\Code\User` on Windows, `~/Library/Application Support/Code/User` on macOS, `$XDG_CONFIG_HOME/Code/User` or `~/.config/Code/User` on Linux); `global` means no variable in a file that is there. No file means VS Code is not set up on this host (a container, a server): no account carries the VS Code role and nothing is held by it (BTN-1540); pointing VS Code at a folder still creates the file.
- The file is rewritten only if it is pure JSON (with comments it is an error in the panel, fix by hand); other keys, indentation and line endings are preserved.
- Switching is impossible while any Claude chat is open in VS Code — a live `sessions/<pid>.json` entry with `entrypoint: "claude-vscode"` in any account folder (polled every 5 s and again before writing); the chain and Even Keel sessions do not interfere. Before writing, the shared configuration is transferred to the folder (`DaemonRefresh.prepare`).
- The account an app sits on is not removed. VS Code picks up the new account after Developer: Reload Window.
- The Claude desktop app is not in the panel: it is launched on an account folder by hand, see below.

## Subscription credits and extra usage (BTN-532)

`RateLimits.overage` (`src/limits/overage.ts`) carries provider facts, with its own source and `updatedAt`, independently of the included usage windows. A newer window-only reading keeps the last extra-usage reading without refreshing its timestamp; `currentLimits` drops one older than the account's latest sign-in. Availability is never consent to spend. BTN-567 chose waiting for included allowance; BTN-577 implements detection and stopping separately from the display indicator.

| Provider | What is read | What stays unknown |
| --- | --- | --- |
| Claude SDK | `rate_limit_info.overageStatus` (`allowed`, `allowed_warning`, `rejected`) gives availability; `isUsingOverage` gives current use. An event naming only overage is accepted too | Availability is not the user's extra-usage switch. No balance, dollar ceiling, amount spent or auto-reload settings |
| Claude background CLI | The checked 2.1.310 `-p /usage` answered with zero turns and zero cost, but no extra-usage line on the checked subscription ([live log](../verified/accounts.md)) | Extra usage stays unknown; no undocumented line parser or extra OAuth endpoint |
| Codex and OpenCode on ChatGPT | `wham/usage.credits`: boolean `has_credits`, boolean `unlimited`, finite decimal-string `balance`. Codex's rollout `token_count.rate_limits.credits` uses the same parser. The live response contained `has_credits: false`, `unlimited: false`, `balance: "0"`; a nonzero balance was not available | These are usage credits, not USD. Other observed fields (`overage_limit_reached`, approximate message counts) do not establish auto-reload or a monetary ceiling and are not displayed; `rate_limit_reset_credits` is not extra usage, see below |
| Copilot and OpenCode on Copilot | From the same quota snapshot as the displayed allowance: boolean `overage_permitted` and a nonnegative finite `overage_count`. The live response had false and zero. The existing personal premium-request billing fallback also sums Copilot `netAmount` as USD spent this month | No dollar budget or auto-reload setting; an accumulated count or bill does not prove a session is spending now. Billing uses net amounts after discounts, never gross charges for included requests ([GitHub API](https://docs.github.com/en/rest/billing/usage#get-billing-premium-request-usage-report-for-a-user)); the fallback is not queried in addition to a successful quota answer |
| OpenCode Zen | No verified balance endpoint usable by the account adapter was found; no request or balance is invented | The official [billing page](https://opencode.ai/v2/docs/console/billing/) describes the Console balance and auto-recharge; the [API overview](https://opencode.ai/v2/docs/console/api/) does not specify a balance response contract. The upstream [balance API request](https://github.com/anomalyco/opencode/issues/10448) remains open. Console scraping and browser cookies are not used |

On the wide accounts page, **Extra usage** follows the included windows in the common grid: a credit balance, paid USD spent, on/off permission, availability, or `—` for an unknown source. Keyboard-accessible tips name the source, its age and what it does not report. The drawer and widths up to 760 px show no extra column and keep `tightestWindow` unchanged.

An amber **on credits** chip appears beside the name on the page, in the drawer and on the active header account only while a session is working and the extra-usage evidence is at most ten minutes old. Claude needs an explicit `isUsingOverage: true`. ChatGPT needs available credits plus an exhausted included window whose reset is still ahead; its tip states that spending is inferred. Idle, resting, waiting or signed-out accounts do not get the chip. Copilot's historical amounts do not get it either. Extra usage does not enter the red problem band. Positive balances, actual paid use and automatic refresh through the live service remain [unverified](../unverified/accounts.md#subscription-extra-usage-btn-532); BTN-531 owns that check.

**Banked limit resets** (BTN-1269). `wham/usage.rate_limit_reset_credits` is how many resets of the limit the ChatGPT account has banked: `RateLimits.resets` keeps `available_count` and `applicable_available_count` (`null` when absent) with their own `updatedAt`. Like the model weeks, they outlive a newer snapshot that does not tell them (a rollout, the hub's copy) and are dropped by `currentLimits` when older than the latest sign-in. The account row shows "Resets: N" under the name while the count is above zero, the applicable count in its tip; a narrow row shows it at the head of its menu. There is no button: the user spends a reset in Codex or on chatgpt.com, Even Keel never calls the consume route. The expiry is only in the separate `wham/rate-limit-reset-credits` (`credits[].expires_at`), which is not asked: one more request per poll, which Codex itself leaves out of background polls. Unchecked with a nonzero count: [unverified](../unverified/accounts.md#banked-chatgpt-limit-resets-on-the-account-card-btn-1269).

### Stopping paid subscription usage (BTN-577)

The stop log distinguishes the signal: Claude SDK, ChatGPT credits and permitted Copilot overage say `paid usage detected`; Claude's exhausted `/usage` window says `included allowance exhausted; paid usage possible, not confirmed` (BTN-937). The source travels beside the current evidence and is not saved in the hold. A pending stop retried without matching fresh evidence uses the cautious wording too. The retained `OVERAGE_LIMIT_TEXT` and recovery stay unchanged, including for old holds. The page does not display that internal text; its policy tip explains that an exhausted Claude allowance does not confirm payment.

`overageLimit` accepts evidence at most ten minutes old, including the boundary, and rejects future readings. It checks the window and credit timestamps independently. For a live, busy current chain session, Claude SDK `isUsingOverage: true` is direct evidence; Claude background CLI requires an exhausted `/usage` window with a future reset; Codex/OpenCode on ChatGPT require an exhausted included window and available credits; Copilot/OpenCode on Copilot require an exhausted monthly quota and `overage_permitted`. Historical counts and bills alone never stop a session, nor does a positive balance without an exhausted window. Missing evidence is not proof that spending has stopped. Zen has no invented balance source. API-key recovery is unchanged; Copilot tokens with subscription quotas still use the quota policy.

Only the current managed session id is eligible, including on paused chains. The dispatcher saves its handoff snapshot and limit hold before invoking its own `Agent.stop`, then records successful stopping. The hold survives disappearance from the monitor and service restarts; it waits for a known reset or another ready account with usable allowance, and a poll that shows the window open before the named reset ends it as on any limit (`Handovers.reopenEarly`, EKR-125; a spent spending cap still waits). Warm recovery resumes the session; cold recovery hands off in the same worktree and branch. Neither repeats an already successful stop. An unknown reset remains unknown, without a speculative retry timer. `LimitsWatcher.limits` combines the newest windows and credit facts in the same `chatgpt:` pool, after each contributor's sign-in boundary; switching between Codex/OpenCode cannot bypass an exhausted pool. Poll frequency remains unchanged.

Available paid usage adds an amber warning on the account row, in both the page and drawer. Its tip explains detection delay and recommends provider spending controls for chain accounts, with a link beside it. This is a reaction after a request or poll, potentially five minutes late, not a zero-charge guarantee. Disable additional usage, disable automatic credit reload, or set a provider monthly cap where supported ([Claude](https://support.claude.com/en/articles/12429409-manage-usage-credits-for-paid-claude-plans), [ChatGPT](https://help.openai.com/en/articles/12642688-using-credits-for-flexible-usage-in-chatgpt-personal-plans)). No global or project spending opt-in is added, and a session's nominal dollar budget is not an extra-usage ceiling. Paid live checks require separate consent: [remaining checks](../unverified/accounts.md#paid-subscription-usage-stops), manual task BTN-580 alongside BTN-531.

## A machine's accounts (BTN-1584)

A machine elsewhere's view (its accounts page `/accounts?machine=<id>` and the header's "Accounts" with the machine picked, [machines](../machines.md), "Signing in on a machine") gives each of the machine's own folders, signed in or not, the hub row's menu (`AccountRowMenu`): Even Keel, VS Code, Rename, Remove. A hub subscription with no folder there has no menu, only "Sign in" there. Each item is done on the machine through the link, never on the hub's disk.

- **The commands** (`machineAccountCommands`, `src/service/machine-account-commands.ts`): `machines/account/remove`, `machines/account/keep`, `machines/account/app` (`{machine, account, app}`), `machines/account/name` (`{machine, account, name}`), `machines/account/switch`, each with `account` the machine's folder, and `machines/key` (an API key into a folder of the machine or a new one, `docs/machines/machine-side.md`). The page's row menu sends its usual `account/*` and `machineSend` (`web/src/layout/machineRows.ts`) turns it into the machine's with the row's folder. Remove, Keep and VS Code are the machine's own `account.remove`, `account.keep`, `account.switchApp`: it refuses as the hub would (an app sits on the folder, a chat open in its VS Code), and its refusal reaches the page as its notice code with its words.
- **Removal** waits, as on the hub, for the account's sessions on that machine to end: the machine's card carries `removing` and the account's sessions, so the row shows "removal pending" with Keep; a key folder (`apiKey` on the card) asks "Remove the folder with the key?". The card's `apps` are the machine's VS Code panel, so the VS Code role is the machine's.
- **The name.** The hub knows a machine's account by its agent and e-mail (`hubFolderOf`, `src/account/same-account.ts`: a full sign-in before a long token). Such an account shows and renames the hub folder's name, one for the hub and every machine: Rename on the machine's row writes the hub's folder (`account.rename` on the hub), and a rename on the hub shows on every machine. An account the hub has no folder of — a key, one signed in only there — has its machine folder's own name, renamed there.
- **Even Keel's account** has no machine level: it is the hub's, `accounts[provider]` ("Active account" above), and each machine takes its own folder of the same account (BTN-1311, `docs/chain.md`). Even Keel on a machine's row moves the hub's account of the same e-mail, for the hub and every machine; one the hub has no folder of has the role off with `machines.accountNotOnHub`.
- **Off the link** the menu still opens, its head says the machine is not connected and no item acts; the server refuses any of these commands with `machines.accountsOffline` before sending anything.

## The Claude desktop app

Even Keel does not switch the app's account (BTN-121): each profile needs its own sign-in by e-mail, and the usual ways of starting the app ignore the profile. Whoever needs it launches the app on an account folder by hand. Checked on Windows with the Store (MSIX) build 2.42304.0.0 on 2026-10-17:

- By default the app keeps its data in `%APPDATA%\Claude`, and the Claude Code it starts (its Code tab) works in `~/.claude` with the app's sign-in.
- The Electron flag `--user-data-dir=<folder>` opens a separate profile with its own sign-in, chats and settings. Several profiles run side by side; launching the same folder again focuses its window.
- `CLAUDE_CONFIG_DIR` set when the app is launched reaches the Claude Code it starts: that folder, not `~/.claude`, gets `sessions`, `projects` and `.claude.json`.

```powershell
$env:CLAUDE_CONFIG_DIR = "$HOME\.claude-accounts\<name>"
& "$env:LOCALAPPDATA\Microsoft\WindowsApps\claude-desktop.exe" --user-data-dir="$env:APPDATA\Claude-<name>"
```

- Sign in to a new profile only with "Continue with email". Google sign-in finishes in the browser with a `claude://` link, Windows hands the link to the app without the flag, and the sign-in lands in the default profile instead.
- The Start menu, a taskbar pin, autostart and an update relaunch open the default profile. A Windows shortcut cannot set an environment variable, so a shortcut to a profile has to run the two lines above (e.g. `pwsh -WindowStyle Hidden -Command …`).
- Even Keel cannot launch the app for you: from the service's Windows session 0 it does not start at all ("Access is denied").
- The shared configuration in the folder is as fresh as the last Even Keel launch there: the app's launch does not transfer it.
- Not checked: the installer (non-Store) build on Windows, macOS and Linux. On macOS the same is packaged by [claude-multiprofile](https://github.com/jmdarre-v/claude-multiprofile).
