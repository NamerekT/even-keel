# Baton

Диспетчер цепочек сессий Claude Code. Берёт открытые задачи проекта из Huly, строит порядок по связям `blocks`, запускает сессию на первую задачу и, когда задача уходит в Done, запускает следующую. Веб-страница показывает цепочку и по каждой сессии — этап, текущее действие и заполненность контекста. Работает службой Windows на рабочей станции пользователя: агенты запускаются только здесь.

Глобальные правила из `~/.claude/CLAUDE.md` действуют полностью. Ниже — только то, что специфично для этого проекта.

## Стек

- Node.js 24 + TypeScript, тесты — vitest.
- Huly — через `@hcengineering/api-client`, тот же клиент, что у git-хуков в `~/.githooks`.
- Сессии — CLI `claude` (`--bg`, `agents --json`) и транскрипты в `~/.claude/projects`.
- Интерфейс — React + Vite в `web/`, сборка в `dist/web`, её отдаёт сервер; маршруты клиента сервер отвечает `index.html`. Типы состояния клиент берёт из `src/state.ts` — там только типы, без `node:*`. `npm run dev:web` — Vite с прокси `/api` на `BATON_URL` (по умолчанию `:4747`), `npm run dev:fake` — вёрстка на фейковом состоянии без Huly и сессий (`?link=stale|connecting` — состояния связи, `?chain=idle` — без активной цепочки, чтобы проверить запуск).
- Хостинг: self-hosted Forgejo, приватный репозиторий.

## Задачи

Работа по этому репозиторию ведётся через трекер Huly, проект `BTN`.
Правила, статусы и порядок действий — скил `huly-tracker`, читать его перед созданием задачи или началом работы по ней.

- Код пишется только под активную задачу.
- Ветка: `btn-<номер>/short-description`. Коммит: `[BTN-<номер>] Message`.
- Содержимое задач (заголовки, описания, комментарии) — на русском.
- Сессия доводит задачу до `main` сама: после одобрения ревьюера сливает ветку (`git merge --no-edit` в основной рабочей копии), пушит `main` и удаляет ветку задачи локально и на origin. Пользователю — отчёт о сделанном, а не команда слияния.

Исключение из скила: прямая работа с API Huly здесь разрешена — это суть проекта.

## Инварианты

1. **Остановившуюся сессию диспетчер не трогает.** Вопрос, ошибка, лимит — ничего не происходит. Пользователь отвечает с телефона через Remote Control или сам двигает задачу в Huly.
2. **Huly — источник правды о статусах.** Своё у диспетчера только порядок цепочки и пауза.
3. **Секретов в репозитории нет.** Адреса и учётки — из окружения или локального файла вне git; в репозитории только `.env.example` с фейками.
4. **Пароль Windows диспетчер не принимает и не хранит.** Учётку службы пользователь вводит сам.

## Служба Windows

- Хост службы — `service/BatonService.cs`, собирается штатным `csc.exe` из .NET Framework при установке, сторонних обёрток нет. Держит `node --import tsx src/main.ts` в корне репозитория, перезапускает при падении, пишет вывод в `logs/baton.log`. Для отладки без службы: `BatonService.exe <корень> <node.exe> --console`.
- `service/install.ps1` и `service/uninstall.ps1` — из PowerShell 7 от администратора. Пароль учётки скрипт не спрашивает: пользователь вводит его на вкладке «Вход в систему» в services.msc, она же выдаёт право «Вход в качестве службы».
- Служба читает `.env` и `baton.config.json` из корня репозитория; порт не должен быть занят ручным запуском.
- Служба отдаёт собранный `dist/web`: `install.ps1` запускает `npm run build`. После обновления кода — снова `install.ps1` (или `npm run build` и перезапуск службы), иначе страница старая или 503.
- `claude --bg` ходит через демон-супервизор (`claude daemon run`, канал `\\.\pipe\cc-daemon-…`). Остановка службы фоновые сессии не убивает — они дети демона.
